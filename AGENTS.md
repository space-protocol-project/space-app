# Правила работы с кодом

- Общайтесь с пользователем по-русски. Сохраняйте понятные имена и низкую когнитивную сложность.
- По указанию пользователя работайте непосредственно в `main`. Отдельную ветку создавайте только по его прямому запросу.
- Используйте свежие стабильные версии Flutter, входящего в него Dart SDK, Go и зависимостей, когда они совместимы с проектом. Перед обновлением проверяйте актуальные выпуски; после обновления синхронизируйте CI и выполняйте проверки. Фиксируйте конкретную причину отложенного обновления. Предварительные версии применяйте только по явному запросу.
- Для рукописного Dart приложения и собственных пакетов рабочий предел — COG 15 на функцию; стремитесь к 10 и ниже. Учитывайте inline-замыкания и `if`/`for` в коллекциях Flutter.
- Разделяйте код по обязанностям: проверка данных, применение событий, работа с ресурсами, отображение и пользовательские действия. Не ослабляйте проверки безопасности ради метрики.
- Прикладное состояние и асинхронные пользовательские операции размещайте в Bloc/Cubit. Локальные анимации, фокус, наведение и контроллеры ввода оставляйте в виджетах.
- Для состояний с повторяющимися полями и копированием используйте Freezed. Генерация из `client`: `dart run build_runner build`; исходные модели и сгенерированные `.freezed.dart` сохраняются вместе. Сериализация протокола и проверка недоверенных данных остаются явными.
- После изменения Dart выполняйте `python tools/check_complexity.py`, `flutter analyze` и подходящие тесты из `client`. Для изменённых собственных пакетов запускайте анализ также из каталога соответствующего пакета. Подготовка анализатора и границы метрики описаны в `docs/READABILITY.md`.
- Не повышайте порог и не добавляйте исключения для отдельных функций, чтобы скрыть превышение. Сгенерированные файлы и сторонний код исключаются из измерения явно.
