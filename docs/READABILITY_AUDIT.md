## Управление состоянием

Прикладное состояние остаётся в BLoC/Cubit. В виджетах остаются отображение, локальные анимации, фокус и `TextEditingController`; отдельный BLoC для каждого наведения не нужен.

- `MessageSearchController` владеет задержкой поиска, областью запроса, курсором, ошибкой и результатами. Номер поколения не позволяет старому ответу или ошибке заменить новый запрос. Закрытие отменяет таймер. Выдача ограничена 200 сообщениями, совпадения определяются парой «канал, сообщение».
- `ChannelFilesController` перенесён из `ui/channel_files.dart` в `src/channel_files_controller.dart`. Старый путь экспортирует контроллер для совместимости. `copyWith` сохраняет неизменяемые поля без ручного перечисления при каждой загрузке.
- Существующие `EventController`, события запросов и порядок завершения команд сохранены. Публикация состояния по-прежнему предшествует завершению ожидающего запроса.

Исходные объявления содержат параметры, значения по умолчанию и предметные методы. Генерируются свойства, копирование и служебные реализации. В `build.yaml` перечислены 11 библиотек, поэтому генератор не сканирует тесты и весь проект при каждом запуске.

Из `client`:

```powershell
flutter pub get
dart run build_runner build
```

Сгенерированные `.freezed.dart` хранятся в Git рядом с исходными библиотеками. В CI добавлен повторный запуск генератора с проверкой изменённых и незарегистрированных результатов.

Для существующих состояний задано `equal: false`: сохраняется прежняя семантика публикации каждого нового снимка. `ChatState.fromController` уже копирует и замораживает protobuf и коллекции; дополнительная оболочка Freezed для этих коллекций отключена, чтобы сохранять идентичность неизменившихся списков. Это проверяет существующий тест `bloc_events_test.dart`.

Криптографические структуры, журналы и проверка ответов сервера не заменены автоматической JSON-сериализацией. Здесь важны порядок проверки полей, строгие ограничения и отказ при повреждении данных.
