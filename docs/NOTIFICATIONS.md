# Уведомления — локальный срез v0.5

В настройках приложения есть режимы «Выключены», «Скрывать содержимое» и
«Показывать текст сообщения». По умолчанию уведомления выключены. Настройка
сохраняется на этом устройстве. Реализован настольный адаптер для Windows,
macOS и Linux, включая присоединённые закрытые MLS-каналы. Мобильный push
и доставка новых сообщений после завершения процесса остаются открытыми
задачами. Запуск по уже показанной карточке Windows описан ниже.

## Поведение

- Наблюдаются обычные читаемые каналы подключённых пространств, пока процесс
  приложения запущен. Первый снимок каталога задаёт границу без уведомления
  обо всей старой истории. После разрыва сети приходит одна сводка на канал.
- Повтор, уменьшение номера последовательности, правка и реакция не вызывают
  повторного уведомления. Прочитанное сообщение и сообщение известного
  собственного автора пропускаются. Для неоткрытого канала каталог не содержит
  автора: возможна общая сводка о собственном сообщении с другого устройства.
- Открытый чат в активном окне не уведомляет. Архивные, невидимые и нечитаемые
  каналы исключены. Доступ повторно проверяется перед системным вызовом.
- В скрытом режиме ОС получает только «Space» и «Новое сообщение». Адрес,
  идентификаторы личности/канала и цель перехода не передаются ОС. На Windows
  цель сохраняется в защищённом хранилище, а карточка получает случайный
  одноразовый ключ. На macOS/Linux цель пока остаётся в памяти приложения.
- Предпросмотр явно передаёт ОС название пространства/канала и до 220 символов
  доступного текста. Для неоткрытого канала без локального текста используется
  общая надпись. ОС может сохранить показанный текст в своём центре уведомлений;
  отзыв доступа или выключение настройки не гарантируют удаления этой копии.
- Нажатие снова проверяет сохранённое пространство, личность и права. Оно
  показывает окно и канал, затем переходит к доступному сообщению. Неизвестные
  адреса из нажатия не подключаются. На Windows поддержан запуск закрытого
  приложения; для macOS/Linux восстановление после завершения процесса пока
  остаётся отдельным этапом.

## Ограничения ресурсов и систем

Очередь содержит не более 32 каналов, обновления одного канала объединяются.
Адаптер держит не более 64 карточек на сеанс, повторно использует карточку
канала и закрывает прежнюю перед заменой. Очередь уведомлений не является
очередью сообщений и не хранит их текст на диске. На Windows сохраняется
только защищённая цель перехода.

Windows при включении может создать или обновить ярлык Space для регистрации
уведомлений. Linux требует `libnotify`; `libnotify-dev` добавлен в CI сборки.
Системный запрет уведомлений или режим концентрации могут скрыть карточку.
Успешный вызов плагина не доказывает, что ОС показала её пользователю.
Физический Android не используется. Ручная приёмка macOS/Linux и фактического
нажатия Windows остаётся отдельной проверкой, а не подменяется тестами.

Проверка источников Linux-адаптера выявила отдельный путь `ClickAction` вместо
нажатия тела карточки. Для Linux теперь задаётся локализованная кнопка
«Открыть чат» и обрабатывается действие с индексом 0. Очистка отключает оба
обработчика, чтобы старая карточка не открывала канал после выключения режима.
После выбора канала и поднятия окна повторно проверяются текущая личность,
канал и права: отзыв доступа во время ожидания не приводит к переходу.

## Проверки

`chat_notifications_test.dart` проверяет начальную границу, повтор, откат,
переподключение, личности, ACL, прочтение, собственные сообщения, неверные
цели нажатия и сохранение настройки. `system_notifications_test.dart`
проверяет системный вызов, замену карточки, обратный вызов нажатия и очистку
через подменённый платформенный канал; адрес не передаётся в аргументах ОС.

`notification_navigation_test.dart` проверяет переход в другое пространство
и канал, неизвестный сервер, подмену личности, отзыв прав до нажатия и во
время поднятия окна. Вместе с проверками системного адаптера на трёх платформах
получено восемь успешных целевых тестов. В `desktop.yml` подготовлен запуск
этих проверок в матрице Windows/macOS/Linux; удалённый CI пока не запускался.
Полный локальный прогон после этих изменений: **514 тестов прошли, 13 штатных
пропусков, ошибок нет**; анализ без замечаний, COG ≤15.

Попытка настоящего нажатия Windows выполнялась через computer-use на отдельном
тестовом окне. Окно и кнопка повторного показа доступны, системная карточка не
возвращается как доступное для управления окно. Поэтому реальное нажатие
Windows остаётся неподтверждённым; тестовая подмена обратного вызова не
считается его ручной приёмкой. Настройки ОС и профиль пользователя не менялись.

Повторный изолированный прогон новой функции и двух упавших файлов: 33 теста
прошли. Финальная Windows release-сборка и горячее обновление тестового окна
успешны, ошибок выполнения нет. Настоящая Windows WinRT History вернула XML
проверочной карточки «Space — проверка / Новое сообщение»; это подтверждает
приём карточки ОС. После проверки тестовая карточка и созданный тестовый ярлык
удалены. Фактическое нажатие пользователем на системную карточку не проверено.

Локальный общий прогон 17 октября: 500 успешных тестов, 13 штатных пропусков,
два сбоя teardown (`home_update_journal_test`, `queued_files_test`) с Windows
ошибкой 145 при удалении временного каталога. Ранее тот же сбой появлялся в
других файловых тестах; это не считается зелёным общим прогоном. Анализ Dart
не нашёл замечаний, предел COG 15 сохранён. Отдельные проверки новой функции
и повтор упавших файлов фиксируются отдельно от общей приёмки.

После устранения сбоев очистки полный повтор с обычным параллелизмом:
**507 тестов прошли, 13 штатных пропусков, ошибок нет**. Анализ Dart без
замечаний, COG ≤15. Общий помощник `test/support/temp_directory.dart` заменяет
прямую очистку временных каталогов тестов. Он проверяет родительский Temp,
префикс и тип каталога, повторяет только ошибки Windows 5/32/145 максимум
пять раз с ограниченной задержкой. Постоянная блокировка и остальные ошибки
по-прежнему завершают тест неуспешно. Пять отдельных проверок подтверждают
границы удаления и повторов. Рабочая логика хранения и проверки данных не
ослаблялись; прежний неуспешный прогон выше оставлен как история проверки.

Следующие срезы: мобильная доставка
без текста на push-сервисе; восстановление перехода после запуска приложения;
ручная приёмка платформ. Серверный поиск обычных каналов и локальный поиск
закрытых каналов остаются следующей частью v0.5.

## Закрытые MLS-каналы

Настольная доставка работает и для уже присоединённых закрытых каналов
подключённых пространств. Используется общая настройка: выключено,
скрывать содержимое или показывать предпросмотр. Предпросмотр намеренно
передаёт расшифрованный текст операционной системе; сервер и push-посредник
не получают дополнительных открытых данных. В скрытом режиме остаются
только «Space» и «Новое сообщение». Имена файлов и ключи вложений в ОС
не передаются; сообщение только с файлами получает общую надпись.

Таймер раз в три секунды проверяет до четырёх каналов по кругу, без
перекрывающихся проходов. Недоступные, архивные и неприсоединённые группы
пропускаются. Фоновая проверка не присоединяет устройство и не подтверждает
незнакомые ключи. Используется тот же последовательный MlsClient, что и в чате:
расшифровка, проверка отправителя и сохранение состояния завершаются до
формирования уведомления. Неизвестный отправитель, ошибка проверки или
откат хранилища не дают уведомления.

Начальная граница берётся из защищённого курсора. Повторная синхронизация,
импорт архива, собственная личность на любом её устройстве, реакции и
служебные изменения группы не создают карточек. При нескольких новых
сообщениях показывается последнее входящее; общая очередь объединяет
обновления канала. Перед показом и переходом сообщение повторно читается
из защищённого хранилища, проверяются актуальные права, группа и личность.
Смена настройки отменяет результаты незавершённого опроса. После нажатия
переход привязан к группе и ключу сообщения; список прокручивается к нему
ограниченным поиском. При отсутствии доступа или истории перехода нет.

Мобильный push и получение после завершения приложения остаются в плане.
Нативная приёмка доставки/нажатия на каждой ОС также остаётся отдельной
проверкой. Локальные тесты системного адаптера не подменяют эту приёмку.

Проверка MLS-среза: полный локальный прогон — **531 тест прошёл, 13 штатных
пропусков**. После уточнения привязки интерфейса к личности/сеансу/группе
повторно прошли **37 целевых тестов**, включая все три режима в оболочке,
нажатие MLS-уведомления и прокрутку к сообщению вне экрана. Анализ без
замечаний; 165 рукописных файлов, 1590 функций, максимум COG 15, превышений
нет. Два сквозных сценария с настоящим локальным runtime/PostgreSQL и
нативным MLS прошли; первый дополнен проверкой уведомления после проверенного
приёма и отсутствия повтора. Физический Android не использовался.

Заключительная проверка прокрутки на истории из 100 сообщений с обратным
порядком хранения и повтор доставки в оболочке: **10 тестов прошли**.
Финальная Windows release-сборка успешна. Изолированное тестовое окно MLS
запущено, горячее обновление прошло, ошибок выполнения не найдено; окно
закрыто. Оно использовало фиктивную историю, без профиля и переписки
пользователя. Это не ручная приёмка системного уведомления Windows.

## Запуск по карточке Windows

Карточка Windows использует protocol activation `space-notification:<token>`.
В ней нет адреса сервера, личности, канала, номера сообщения или MLS-ключа.
Ключ — 128 случайных бит. Сопоставление хранится через `PlatformKeyStorage`
в отдельном разделе защищённого хранилища; текст и ключи файлов не сохраняются.
Максимум 64 цели, срок семь суток. Замена карточки канала отзывает старый ключ.
Нажатие атомарно в пределах процесса потребляет ключ; повтор ничего не открывает.
Отключение уведомлений очищает цели и карточки. При повреждении хранилища
навигация не выполняется. Это не резервная копия и не восстановление MLS-ratchet.

Установщик регистрирует обработчик протокола и удаляет его при удалении
приложения. Переносимый запуск регистрирует путь текущего исполняемого файла
при первом показе карточки. После перемещения переносимой папки нужно заново
показать уведомление. Аргумент протокола проверяется строго: одна строка,
фиксированный префикс и 32 шестнадцатеричных символа. Он не используется как
команда, путь или адрес сервера. Данные от другого процесса также считаются
недоверенными. ОС может хранить показанный предпросмотр по прежним правилам.

Новый процесс передаёт нажатие уже работающему экземпляру по проверенному
пути exe. Именованный mutex не позволяет двум процессам одного exe одновременно
открывать профиль. Первый запуск удерживает нажатие до готовности Dart, загрузки
настроек и каталога сохранённых пространств. Нажатия обрабатываются последовательно.
При временном отсутствии сети цель остаётся в памяти до следующего изменения
подключения; ещё одно закрытие приложения эту уже потреблённую цель не сохраняет.

Перед переходом заново проверяются сохранённый сервер, текущая личность,
архивность, видимость и право чтения канала. После каждого ожидания повторно
проверяется актуальность запроса; новая цель или изменение настроек отменяют
старый переход. Для MLS дополнительно проверяется текущая группа и наличие
проверенного сообщения в локальном хранилище. Содержимое не берётся из URI.
Обычное сообщение вне последних 100 записей загружается одной страницей
истории перед `sequence + 1`, с повторной проверкой сеанса/личности/канала/ACL.
Граница основной постраничной истории и курсор подписки не меняются.

macOS/Linux по-прежнему обрабатывают нажатие в работающем приложении. Запуск
по их системным карточкам, мобильный push и получение новых сообщений при
завершённом процессе требуют отдельных платформенных адаптеров.

Проверка 17 октября: общий прогон после добавления сценария выключенных
уведомлений — **568 тестов прошли, 13 штатных пропусков**. После уточнения
порядка начальной загрузки настроек повторно прошли **30 целевых тестов**:
холодный запуск, загрузка настроек уже в созданной оболочке, отказ при выключенном
режиме, одноразовые/заменённые/просроченные ключи, лимит, параллельные записи,
переход между пространствами, старое сообщение на истории 100 000 и отзыв ACL
во время запроса. Анализ Dart без замечаний; COG максимум 15, превышений нет.
Один промежуточный тест начальной загрузки завис из-за ожидания fake-async
очереди внутри runAsync; fixture исправлена, финальные 30 проверок прошли.

Настоящий Windows runner проверен отдельно с выделенным тестовым разделом
PlatformKeyStorage, без переписки и ключей личности пользователя. Новый процесс
передал нажатие текущему окну; повтор ключа не создал второй переход. После
завершения процесса восстановлена и цель MLS. Windows WinRT History вернула
реальный XML тестовой карточки с activationType=protocol и одним непрозрачным
ключом. После закрытия процесса запуск этого URI через системный обработчик
восстановил обычную цель из защищённого хранилища. Это проверка цепочки URI →
новый процесс → хранилище → событие; отдельные widget-тесты проверяют переход
в оболочке. Физическое нажатие мышью на системную карточку не проверялось.
Тестовая карточка, ярлык, обработчик протокола и отдельная запись vault удалены;
прежнее состояние регистрации восстановлено. Windows release-сборка успешна.

Изменения запуска по уведомлению пока локальные. CI схемы 21 к ним не относится;
новый набор тестов добавлен в матрицу desktop.yml для следующей отправки.

Заключительное изолированное окно после последних изменений запущено и закрыто; горячее обновление прошло за 300 мс, ошибок выполнения не обнаружено. Временный параметр format:false и изменения форматирования сгенерированных локализаций устранены; эти файлы совпадают с HEAD. Контроль diff и COG прошёл.
