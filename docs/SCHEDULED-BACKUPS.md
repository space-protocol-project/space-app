# Резервные копии по расписанию

Выпуск v0.6.0: настройки находятся в «Эфире», выполнение принадлежит runtime с возможностью `scheduledBackupsVersion: 1`. Схема PostgreSQL остаётся 22. Старый runtime не позволяет включить расписание: сначала обновите сервер.

## Включение

Откройте настройки копирования, включите расписание и выберите интервал. Автоматическое удаление включается отдельно. По умолчанию обе функции выключены. Допустимы интервалы от 1 до 168 часов, хранение от 3 до 100 копий, возраст от 1 до 3650 дней. Ограничение объёма задаётся в МиБ; ноль отключает этот предел.

Runtime должен работать. Домашний сервер, управляемый приложением, останавливается вместе с приложением; компьютер не пробуждается для копирования. На VPS служба systemd продолжает работу без открытого приложения. Пропущенные интервалы не создают очередь снимков: после запуска делается одна актуальная копия. Настройки проверяются раз в минуту; уже начатая операция может завершиться с прежними настройками. При ошибке повтор не раньше чем через пять минут, предельное время задания — 30 минут.

## Хранение и защита

`backup-policy.json` и `backup-status.json` находятся рядом с `data`. Готовые переносимые ZIP и квитанции SHA-256 хранятся в `scheduled-backups`. Это отдельный набор, не физические копии обновления в `backups`. Снимок выполняется через pg_dump работающей PostgreSQL. После записи проверяются состав ZIP, контрольные суммы и идентичность сервера; квитанция публикуется атомарно.

При включённой очистке старые проверенные копии удаляются, если превышен хотя бы один предел: количество, возраст или объём. Всегда остаются минимум три новые проверенные копии. Поэтому предел объёма мягкий: если три копии больше него, интерфейс показывает предупреждение. Неизвестные, повреждённые, несовместимые и незавершённые файлы автоматически не удаляются. Внешние архивы и пользовательские каталоги не затрагиваются.

Перед снимком проверяется свободное место: два текущих объёма базы плюс 256 МиБ. Это оценка, а не резервирование места; последующая ошибка диска не удаляет прежнюю успешную копию.

ZIP содержит данные сервера и его секретный ключ, не зашифрован паролем и должен храниться приватно. Каталог ограничен правами владельца. Клиентские ключи MLS в серверный ZIP не входят: сохраняйте состояние устройств отдельно. Восстановление выполняется через обычный импорт с предварительной проверкой архива. Политика и статус расписания в переносимый архив не включены; на новом компьютере включите расписание явно.

## Проверки

Локальные автоматические тесты проверяют перезапуск, пропущенные интервалы, отключённую очистку, минимум три копии, предел объёма, повреждения, ссылки, нехватку места и отмену задания. Настоящая PostgreSQL проверяет создание копии работающей базы и импорт в отдельное окружение: совпадают идентичность и байты, записи после снимка отсутствуют в восстановленной базе. Тесты включены в сборку runtime трёх ОС; приложение проверяется отдельным заданием хранения. Устройства и эмулятор Android не используются.
