# Автоматический проброс порта и смена IP

В готовящемся выпуске приложение и runtime поддерживают автоматические сетевые настройки. В опубликованном runtime v0.3.3 их ещё нет; приложение проверяет возможность `automaticNetworkVersion: 1` перед запуском.

## В приложении

1. Остановите свой сервер и откройте «Эфир».
2. Включите «Автоматический проброс порта». Runtime попросит текущий IPv4-шлюз временно перенаправить внешний TCP-порт на локальный порт Space.
3. Если используете меняющийся публичный IPv4, включите «Обновлять публичный IP». Первый адрес должен быть IPv4; домены и дополнительные адреса автоматически не заменяются.
4. Сохраните настройки и запустите сервер. Ссылка и QR обновляются после изменения адреса.
5. Запустите диагностику. «Шлюз подтвердил проброс» означает ответ роутера; отдельное внешнее подключение по-прежнему необходимо для наблюдения доступности из интернета.

Оба переключателя выключены по умолчанию. Если автоматизация включена, можно задать до семи основных адресов: восьмое место зарезервировано для предыдущего автоматического маршрута.

## Отдельный сервер

При первом запуске нового пространства:

```sh
./space-server start -data ./space-home -auto-port-mapping -auto-public-ip
```

С постоянным доменом достаточно `-auto-port-mapping` и `-address https://space.example.org:8443`; DNS обновляется отдельно. Флаги первоначального запуска сохраняются в конфигурации и не заменяют настройки существующего пространства. Установщик systemd по умолчанию не включает проброс портов.

Для существующего пространства остановите сервер и добавьте в `space-home/config.json`:

```json
{"auto_port_mapping": true, "auto_public_ip": true}
```

Это поля существующего документа, а не замена всего файла. Сохраните остальные поля, затем запустите сервер. `space-server doctor -home-data ./space-home/data` покажет свежий статус аренды.

## Поведение и ограничения

- Только TCP-порт Space, только текущий IPv4-шлюз. Последовательность: PCP, NAT-PMP, UPnP IGD. IPv6 остаётся отдельным прямым маршрутом без NAT-проброса.
- Запрашивается аренда 600 секунд. Runtime проверяет её каждые 15 секунд и продлевает после половины подтверждённого срока. При штатной остановке удаляет своё правило; после аварии конечная аренда должна истечь на роутере.
- Для UPnP не заменяется занятый порт; перед удалением сверяются внутренний адрес, порт и случайная метка владельца. Постоянные аренды не принимаются. PCP связывает ответы с nonce. NAT-PMP не имеет такой криптографической привязки: локальная сеть и шлюз должны быть доверенными.
- При активной аренде адрес берётся у роутера при её создании/продлении. Без аренды публичный IPv4 проверяется через HTTPS ipify не чаще раза в минуту. VPN может изменить обнаруживаемый адрес.
- Новая версия адресов подписывается прежним ключом. Сертификат, server ID и постоянная identity_origin не меняются. Домены и дополнительные маршруты сохраняются. Подключённые клиенты проверяют подписанное объявление по heartbeat не чаще раза в 45 секунд и сохраняют новые маршруты.
- Старый адрес остаётся запасным до следующего автоматического изменения. Если ни один известный адрес уже недоступен, клиент не может узнать неизвестный новый IP: нужен DDNS, туннель/relay или новое проверенное приглашение.
- Проброс не обходит CGNAT, двойной NAT или запрет входящих соединений провайдером. Он не открывает файрвол Windows/Linux. Эти ограничения показываются диагностикой, а независимый внешний пробник и relay остаются отдельными задачами.
- Состояние аренды хранится приватно в `data/automatic-network.json`, имеет ограниченный срок актуальности и удаляется при остановке. Оно не является подтверждением внешней доступности.

## Проверки

Автоматизированные проверки используют локальные UDP- и HTTP-шлюзы: PCP/NAT-PMP создание, продление, адресное удаление, nonce/порт/размер ответа; UPnP владение правилом, запрет перенаправлений и обращений не к шлюзу, бюджет XML. Проверены смена IP с сохранением идентичности, подпись объявления, отказ при откате версии, сохранение настроек после перезапуска и истечение статуса диагностики. Подключение к физическим роутерам разных производителей остаётся ручной приёмкой.
