# Поиск сообщений — локальный срез v0.5

Кнопка поиска и существующее сочетание клавиш открывают поиск в выбранном
канале. Поиск разделов приложения сохранён. Запрос вводится от двух символов,
без учёта регистра; ищется буквальная подстрока в исходном тексте сообщения.
Markdown не преобразуется в отдельный поисковый документ. Содержимое файлов,
имена вложений и морфология пока не включены.

## Обычные каналы

Новый `ContentService.SearchContent` ищет в серверной истории одного канала,
а не только в загруженном клиентом окне. Каждая страница повторно проверяет
сеанс, видимость и чтение канала в транзакции. Серверный поиск MLS запрещён.
Удалённые сообщения исключены, правки учитываются по текущей записи. Имена
участников и метаданные вложений возвращаются как у обычной истории.

Запрос — 2–128 Unicode-символов, до 512 байт. `%`, `_` и SQL-фрагменты
считаются буквальным текстом; SQL использует параметры. Приведение регистра
задаётся таблицей Unicode Go и не зависит от локали домашней PostgreSQL.
Результаты идут от новых к старым, до 50 на страницу. Следующая страница
задаётся `before_sequence`, строго меньше последнего номера. Вставка новых
сообщений не сдвигает уже просмотренную границу. Клиент проверяет канал,
порядок, дубли, совпадение текста и курсор до показа результатов.

На поиск отводится три секунды, включая получение соединения и проверки.
Дополнительный полнотекстовый/триграммный индекс пока не создаётся: большие
архивы могут потребовать отдельного этапа оптимизации. Тайм-аут показывает
ошибку, а не выдаёт неполный результат как полный. В старом runtime новый
RPC отсутствует: нужно обновить runtime; автоматического перехода на другой
транспорт или отправки запроса MLS на сервер нет. Существующий предел
первоначальной синхронизации самого чата (11 страниц по 100 записей) этим
срезом не меняется. Постраничное открытие больших историй нужно завершить
отдельно: серверный поиск не отменяет ограничения подключения такого чата.

## Закрытые каналы

Поиск читает защищённое локальное MLS-хранилище. Поисковая строка не передаётся
в RPC; новые сообщения ради поиска не загружаются. Учитывается уже доступная
расшифрованная история, включая импортированный архив. Присоединение к группе,
подтверждение устройств и восстановление ratchet поиск не выполняет.
Проверяются группа, присоединение и отсутствие ожидающего отзыва; откат
хранилища блокирует поиск. Реакции не становятся отдельными совпадениями.
При одинаковых исторических номерах порядок уточняется ключом сообщения;
локальная следующая страница привязана к ключу последнего совпадения.
Текущий путь открытия хранилища использует сеанс присоединённого канала;
самостоятельный офлайн-каталог MLS без сеанса ещё не реализован.

## Интерфейс и защита от устаревших результатов

Задержка ввода — 300 мс; страницы добавляются кнопкой «Ещё сообщения».
Панель показывает до 200 совпадений и предлагает уточнить запрос при достижении
лимита. Запросы и отдельный поисковый индекс на диске не сохраняются.
Отключённый обычный сеанс сохраняет прежний поиск по загруженному кэшу.

Смена пространства, канала, личности, сеанса или прав делает результат
недействительным. Панель закрывается при изменении доступа, ответ старого
запроса не подменяет новый. Нажатие открывает сообщение в чате; найденная
серверная запись может быть добавлена в текущее окно без сброса очереди и
истории. Для MLS используется тот же ограниченный поиск позиции, что и для
уведомлений.

## Проверка

`message_search_test.dart` проверяет недоверенную страницу, пределы запроса,
локальную историю MLS и отсутствие вызова refresh, страницы и устаревший
ответ. `search_navigation_test.dart` проверяет переход к ранее не загруженному
сообщению, смену канала и отзыв прав во время запроса. PostgreSQL-тесты
проверяют регистр кириллицы, две страницы, удаления/правки, буквальные запросы,
авторизацию, ACL и отказ серверного поиска MLS. Сквозной сценарий обычных
каналов проверяет настоящий Dart → Connect → runtime → PostgreSQL, включая
поиск исходника ответа. Локальный Go-прогон и этот сценарий прошли.

Итог локальной проверки: **539 тестов приложения прошли, 13 штатных пропусков**;
анализ Dart без замечаний. COG ≤15: 167 файлов, 1611 функций, превышений нет.
Windows release-сборка успешна. Тестовая панель запущена с фиктивными данными,
горячее обновление выполнено, ошибок выполнения не найдено; профиль
пользователя не использовался. Оба настоящих MLS-сценария тоже прошли, первый
дополнен поиском принятого расшифрованного сообщения. Обычный сквозной сценарий
прошёл после подключения нового RPC к Connect-мосту. Физический Android не
использовался. Проверки PostgreSQL выполнялись в отдельных тестовых схемах
локальной базы; пользовательская база не менялась.

## Поиск по нескольким каналам — следующий локальный срез

Переключатель «Во всех доступных каналах» расширяет поиск на читаемые неархивные каналы выбранного пространства. По умолчанию остаётся выбранный канал. Обычные каналы используют прежний SearchContent с серверной проверкой ACL; закрытые — только защищённый локальный архив присоединённых групп. Поиск не присоединяет устройство к группе и не отправляет строку MLS-поиска серверу.

Каналы обходятся последовательно в порядке каталога, внутри канала — от новых к старым. Выдача не является общей хронологической лентой. Один шаг читает максимум четыре страницы пустых каналов или одну непустую страницу до 50 записей; продолжение — кнопкой «Ещё сообщения». Это ограничивает нагрузку также на пространства с большим числом пустых каналов. Общая панель сохраняет предел 200 совпадений.

Курсор привязан к запросу и упорядоченному списку каналов. Чужой канал в ответе, превышение размера, повтор курсора и пустая страница с продолжением отклоняются. Ошибка не сдвигает границу. Запросы и курсоры остаются в памяти. Результаты объединяются по паре канал/ID; совпадение ID между каналами не скрывает сообщение.

Каждый результат подписан названием канала. Нажатие выбирает его и открывает сообщение после повторной проверки сеанса, личности, прав и группы. Изменение каталога прав, пространства или исходного канала закрывает панель и отбрасывает незавершённые результаты. Офлайн-каталог сохранённых MLS-групп реализован следующим локальным срезом: [OFFLINE-MLS-SEARCH.md](OFFLINE-MLS-SEARCH.md).

Проверки: страницы и границы, бюджет пустых каналов, несовместимый курсор, отказ сети и недоверенный ответ; интерфейс с одинаковыми ID; настоящий контроллер оболочки с переходом в другой канал, исключением скрытых/архивных каналов, отзывом прав и сменой канала во время запроса. Контракт runtime и схема базы не менялись.

Проверка этого среза: полный прогон — 555 успешных тестов, 13 штатных пропусков; после добавления отдельного смешанного MLS-сценария — ещё 16 целевых тестов успешно. Он подтверждает, что сервер опрашивается только для обычного канала, неприсоединённая MLS-группа пропускается, а локальный поиск не вызывает refresh. Анализ Dart без замечаний; 171 рукописный файл, 1654 функции, максимум COG 15, превышений нет.

Windows release-сборка следующего среза успешна. Изолированная тестовая панель запущена, hot reload выполнен, ошибок выполнения нет; профиль пользователя и физический Android не использовались. Изменения поиска по нескольким каналам пока остаются локальными после отправки постраничной истории.

Граница завершающей проверки: после успешного анализа и полного прогона добавлен отдельный MLS-тест (16 целевых тестов прошли). Повторный запуск flutter analyze после Windows-сборки завис на LSP initialize; повтор без pub и проверка через Dart MCP также не завершились. Зависшие CLI-проверки остановлены. Предыдущий анализ был без замечаний; свежий результат повторного анализа не заявляется.

Повторная проверка 17 октября завершена: flutter analyze --no-pub прошёл без замечаний (11 секунд). Для обхода зависшего dart language-server использован временный launcher в .local/analysis-sdk: он запускает неизменённый analysis_server_aot.dart.snapshot из того же SDK; flutter analyze получает его через --dart-sdk. Исходный SDK и анализируемый код не менялись.
