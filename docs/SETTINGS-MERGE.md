# Слияние настроек при переносе и восстановлении

## Правила

Один механизм применяется к файлу, зашифрованной передаче каталога и копии на
сервере пространства. Дополнительных служб нет. Импорт настроек включается
отдельно; без этого выбора настройки и их ревизии не меняются.

Ревизия принадлежит каждому из семи переносимых параметров отдельно: тема,
эффекты, палитра, язык, клавиша отправки, масштаб и режим уведомлений.
Она представлена ограниченным вектором логических счётчиков. Ключ вектора —
случайный 128-битный идентификатор установки, значение — положительный целый
счётчик. Идентификатор не является ключом доступа. У принимающего приложения
остаётся собственный идентификатор; идентификатор отправителя не назначается
ему как локальный. Часы, время файла и номер ревизии всего архива не выбирают
победителя. Системная смена яркости при автоматической теме не считается
изменением выбора темы.

- Изменение параметра увеличивает только его локальный счётчик.
- Если один вектор покрывает другой, применяется причинно более новое значение.
- Независимые изменения разных параметров объединяются автоматически.
- При одинаковом значении векторы объединяются без нового пользовательского
  изменения. Повторный импорт не увеличивает счётчики.
- Разные значения с несравнимыми либо одинаковыми векторами — конфликт.
  Пользователь выбирает значение отдельно для каждого такого параметра.
  Выбор объединяет оба вектора и увеличивает локальный счётчик: отклонённый
  вариант уже учтён и не возникает снова при повторном импорте версии 2.

До выбора всех конфликтующих параметров импорт настроек заблокирован.
Можно отключить импорт настроек и восстановить только каталог. Изменение
настроек после предварительного просмотра делает план устаревшим; перед записью
нужен новый просмотр. Применение и пользовательские изменения сериализуются
контроллером настроек.

## Хранение, сбои и версия формата

Значения и векторы сохраняются одним документом настроек, вместе с локальным
идентификатором установки. Прежние отдельные параметры читаются только при
первом переходе и получают локальную историю. Новые записи используют один
формат; параллельных API или двух механизмов слияния нет.

Полный перенос устройства с остановкой исходного приложения перемещает весь
профиль и сохраняет его идентификатор установки. Это другой сценарий, не создание
второго действующего устройства. При чтении старого полного архива новая запись
настроек по умолчанию удаляется после восстановления старых параметров, чтобы
она не перекрыла их при следующем запуске.

Манифест каталога версии 2 добавляет `settings_versions`; значения остаются в
`settings`. Контейнер шифрования и непрозрачный серверный API не меняются.
Чтение документированных файлов версии 1 сохраняется: их исходные байты и
digest не переписываются. У них нет причинной истории настроек, поэтому разные
значения требуют явного выбора, а не считаются более новыми. Это чтение
пользовательских архивов, не совместимость со старым серверным API.

Для v1 различия требуют выбора и при повторном чтении: доказательства, что
неверсионированное значение уже было учтено как причинное изменение, нет.
Повтор явно сделанного выбора является новым решением пользователя.
Возобновление одного уже записанного журнала остаётся идемпотентным.

Перед первым изменением настроек защищённый журнал сохраняет исходный снимок
и полный выбранный результат вместе с ревизиями. Подтверждённый результат
можно повторно применить после сбоя без новой ревизии и дубликатов. Если после
сбоя пользователь уже изменил параметр локально, его последующий выбор
сохраняется и учитывает подготовленное изменение; возобновление не стирает его.
Сбой до записи журнала не считается согласием на импорт.

## Проверка недоверенных данных

Во всех версиях проверяются точный набор полей, значения настроек, размеры,
канонические идентификаторы и целочисленные счётчики. Не более 32 участников
в истории одного параметра; счётчик не превышает 2^53−1. Переполнение или
превышение размера блокирует операцию. История не обрезается молча, поскольку
это могло бы превратить конфликт в якобы более новую версию. Векторы не дают
серверных полномочий и находятся внутри зашифрованного каталога.

## Проверки GitHub CI

Независимые изменения, конкурентные значения, одинаковые значения, устаревшие
копии, явное сохранение локального варианта, повтор импорта, устаревший просмотр,
подмена и превышение лимитов, архив v1, отсутствие согласия, сбой до/после
сохранения настроек, сохранность последующих локальных изменений. Для всех
трёх путей проверяется один механизм; отдельно выполняются нативные аварийные
сценарии и проверка системного хранилища. Результаты будут добавлены после CI.
