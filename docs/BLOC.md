# События и состояния Flutter

Общее состояние приложения управляется `flutter_bloc` 9.1.1. Операции имеют конкретные типы событий; интерфейс получает состояния через BlocBuilder, BlocListener и BlocSelector. Пример разделения отображения и реакций описан в [официальной документации](https://bloclibrary.dev/flutter-bloc-concepts/).

## Области состояния

| Контроллер | События | Состояние |
|---|---|---|
| ChatController | подключение, отправка, выбор канала, прочтение, избранное, история; входящие кадры, изменения и ошибки каталога | ChatState |
| HomeController | загрузка, определение IP, запуск, остановка, обновление, восстановление, тик прогресса | HomeState |
| AppUpdates | проверка, загрузка и установка обновления | AppUpdateState |
| AppPreferences | оформление, язык, клавиша отправки, сохранённые серверы и иконки | PreferencesState |
| ServerPresence | изменение наблюдаемого набора, проверка, результат отдельной пробы | PresenceState |
| ServerWorkspaces | синхронизация, принятие контроллера, подключение, обновление и удаление | WorkspaceState |
| AdminOperations в space_admin_ui | начало, завершение и ошибка административной операции | AdminOperationState |

ChangeNotifier и ручные слушатели состояния приложения удалены. Системные слушатели окна и прокрутки продолжают обслуживать свои механизмы Flutter. В виджетах остаются текстовые поля, черновики форм, навигация, фокус, наведение, а также локальные данные редактируемых административных форм. AdminOperations управляет выполнением запросов этих форм и блокирует двойной запуск.

## Команды и результаты

Методы вроде `controller.connect()` и `controller.send(text)` добавляют соответствующее событие; бизнес-операцию выполняет зарегистрированный обработчик `on<Event>`. Возвращаемый Future завершается после самой операции и публикации последнего состояния. Это позволяет последовательно выполнять подключение, остановку клиента и запуск установщика.

Можно отправить событие напрямую:

```dart
final event = ChatMessageSent('Сообщение');
final completed = event.result;
controller.add(event);
final accepted = await completed;
```

Ожидание результата необязательно. RequestEvent сохраняет результат и для более позднего ожидания; ошибка ожидаемого запроса возвращается вызывающему коду. Неожидаемая ошибка проходит стандартную обработку ошибок Bloc. Наблюдатели не должны сериализовать содержимое событий с профилями, setup-кодами или текстом сообщений; штатное приложение не устанавливает такой журнал.

## Порядок и отмена

Настройки обрабатываются одной последовательной очередью PreferencesCommand с `sequential()`. Так поздняя загрузка или запись не затирает последующее изменение. Публикация PreferencesState имеет отдельный обработчик и не блокируется этой очередью.

Сетевые команды сохраняют проверки busy и поколения сессии. Входящий ChatFrameReceived обрабатывается только для текущей сессии и канала. ChatCatalogChanged/ChatCatalogFailed и PresenceProbeCompleted проверяют своё поколение. Поздний результат удалённого сервера или остановленной подписки не возвращает прежнее состояние.

Домашние операции, установщики и административные изменения не переводятся на restartable: отмена Future не откатывает файловые операции или уже принятый сервером запрос.

## Состояния и интерфейс

ChatState содержит снимки сообщений, каналов, закладок, непрочитанных сообщений и ошибок. Protobuf копируется и замораживается; списки, карты и множества состояний создаются неизменяемыми. Сохранённое состояние остаётся прежним после следующего события. Рабочие данные и сетевые ресурсы остаются внутри контроллера.

BlocBuilder используется для отображения; BlocListener — для реакций shell на настройки, удаление доступа и доступность серверов. Индикатор обновления использует BlocSelector и обновляется только при изменении наличия выпуска. Прогресс runtime и панель настроек имеют собственные подписки и работают отдельно от shell.

Владелец контроллера вызывает `await close()` при асинхронном завершении. Из синхронного State.dispose доступен `dispose()`, который запускает close. Таймеры и подписки освобождаются при закрытии. BlocBuilder/BlocListener автоматически переключают свои подписки при смене переданного контроллера.

## Проверки

`client/test/bloc_events_test.dart` проверяет порядок сохранения настроек, прямую отправку события, сохранение прежних состояний, защиту protobuf, позднее ожидание результата, закрытие с ожидающим запросом, поздний ответ доступности и двойной запуск административной операции. Существующие тесты продолжают проверять курсоры, переподключение, отзыв доступа, черновики, локализацию, TLS и обновления.

В widget-тестах контроллер и его реальные асинхронные операции создаются в одной зоне tester.runAsync. Для действий интерфейса в этой зоне тест даёт очереди событий завершиться перед следующим кадром. Тест отправки проверяет состояние sending после получения события состояния, а не синхронно после добавления команды.

На сервере Go библиотека Flutter не применяется. Сетевой контракт ConnectRPC и серверная доставка событий сохраняются.

Итоговая локальная проверка: 235 тестов Flutter прошли, 4 стандартных пропуска; анализ без замечаний, Windows Release собран, hot reload без ошибок Dart. Изменения находятся в рабочих каталогах, без публикации нового выпуска.
