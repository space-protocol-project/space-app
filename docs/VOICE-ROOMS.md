# Голосовые комнаты: настольный срез

Разработка после v0.6.0, ветка `codex/voice-rooms`. Для работы нужны новый клиент и новый runtime со схемой **23** и `voice_rooms_version: "1"` в discovery. В опубликованный v0.6.0 эта функция не входит.

## Как пользоваться

1. Подключитесь к пространству и откройте «Комнаты».
2. Владелец или администратор создаёт голосовую комнату. Второй участник увидит её в том же разделе.
3. Нажмите «Войти». Микрофон при входе выключен; разрешение и захват запрашиваются при явном включении.
4. В списке отображаются участники и состояние их микрофона/звука. Нижняя панель соединения сохраняется при переходе в чат.
5. Кнопка микрофона включает/выключает передачу. Отключение входящего звука также выключает микрофон. После возвращения звука микрофон остаётся выключенным.
6. «Выйти» останавливает микрофон, закрывает WebRTC и удаляет подключение из комнаты. Закрытие подключения к пространству также завершает разговор.

## Границы первого среза

- Два подключения в комнате, до 128 в процессе runtime. Одно устройство может состоять только в одной комнате.
- Windows, macOS и Linux используют `flutter_webrtc`; нативная сквозная проверка выполнена только на Windows. Android не используется.
- Встроенный Pion пересылает Opus между участниками. Камеры, запись, выбор аудиоустройства, индикатор фактической речи и автоматическое переподключение пока не реализованы.
- Первое подключение рассчитано на локальный компьютер или доступную локальную сеть. STUN/TURN и работа через внешний NAT пока не настроены. Доступность HTTP API через интернет сама по себе не гарантирует доступность медиа.
- Комнаты являются отдельными обычными каналами `voice_room`. Права `read` и `write` задают возможность слушать и говорить соответственно. Текстовые сообщения в голосовой канал не принимаются.
- Звук защищён WebRTC при передаче, но сервер имеет доступ к аудио. Это не MLS/E2EE-комната. Аудио не сохраняется.
- Список обновляется раз в три секунды. Допуск устройства и ACL перепроверяются сервером раз в секунду; пропавшее подключение удаляется по сроку 30 секунд.

## Воспроизводимая проверка Windows

Из корня приложения:

```powershell
./tools/check_voice_rooms.ps1 -Runtime 'C:/path/to/runtime-with-postgres'
```

Стенд создаёт отдельный кластер PostgreSQL на loopback, проверяет миграцию и права комнаты, собирает сервер и запускает два независимых процесса Flutter с временными личностями. Используется настоящий настольный микрофон и нативный WebRTC; воспроизведение в тесте имеет нулевую громкость, чтобы избежать обратной связи. Аудиозаписи не создаются. Проверяются двусторонние пакеты, декодирование, участники, mute/deafen и выход.

После завершения собственная база стенда удаляется, журналы и отчёты остаются в `.local/voice-check-*`. Пользовательские данные runtime не используются. Скрипт собирает специальную точку входа вместо обычного приложения; после проверки восстановите сборку командой `flutter build windows --release --no-pub` из `client`, предварительно подключив `tools/mls_environment.ps1`.

Модульные и виджетные проверки находятся в `client/test/voice_controller_test.dart` и `client/test/voice_widgets_test.dart`. Проверка пакетов и декодирования не заменяет ручную оценку слышимости, задержки и качества разговора между двумя людьми на разных компьютерах.

## Результат проверки 18 октября 2026

Два полных нативных прогона прошли: независимые процессы Windows подтвердили вход, имена двух участников, двустороннее аудио и декодирование, mute/deafen и выход. В повторном прогоне клиент A принял 7 пакетов и декодировал 6240 сэмплов, B — 2 пакета и 1920 сэмплов; счётчики сняты сразу после подтверждения передачи. Отчёты: `.local/voice-check-72537f7461354d77a64a1cdda7f96e60/{A,B}.json`.

Также прошли 15 Flutter-тестов голоса и каналов, `flutter analyze`, проверка когнитивной сложности (максимум COG 15, превышений нет), обычная Windows release-сборка, `go test ./...`, `go vet ./...` и `buf lint`. В отдельной PostgreSQL прошли проверки голосового канала, обычных каналов и доставки MLS. Новый медиасервис локально не проверялся с `-race`; результат старого CI прототипа на него не переносится.
