# Перенос домашнего пространства на другой компьютер

На исходном компьютере откройте панель домашнего сервера и нажмите
«Экспорт пространства». Выберите место для ZIP-архива. Приложение остановит
сервер, снимет согласованную копию и снова запустит его, если он работал.

На новом компьютере установите Space и выберите «Импорт пространства»
на главной странице. В панели сервера нажмите кнопку импорта, укажите новый
публичный IPv4 и выберите сохранённый архив. Если адрес не изменился,
поле IPv4 можно оставить пустым. Импорт доступен только до создания
пространства на этом компьютере и не заменяет существующую базу.

После выбора архива приложение проверяет его состав, контрольные суммы и
совместимость схемы без восстановления базы. В отдельном окне показываются
идентификатор пространства, версия данных, число файлов и распакованный объём.
Восстановление начинается только после нажатия «Начать восстановление».
При отмене, повреждении архива или отсутствии поддержки проверки в runtime
импорт не запускается. Изменение архива после проверки требует новой проверки.

Проверка доступна начиная с приложения и runtime v0.4.3 (этап v0.6).
Нужен runtime с `portableInspectionVersion: 1`; v0.4.2 её не поддерживает.
Проверка архива не заменяет проверку восстановления базы на новом компьютере.

После импорта запустите сервер и направьте порт 8443 роутера на новый
компьютер. Рядом со ссылкой появится QR. Передайте участникам новую ссылку
или QR: прежний адрес автоматически не перенаправляется.

Архив переносит сообщения, каналы, настройки, участников, разрешения,
историю смены ключей и ключи сервера. На новом компьютере создаётся новая
PostgreSQL и собственный пароль базы; временные токены сессий не переносятся.
Для переноса используется логическая копия PostgreSQL, а не файлы старой
установки. Формат не привязан к Windows, macOS или Linux. Максимальный
распакованный размер архива — 2 ГиБ; нужна та же версия схемы сервера.

Архив **не зашифрован и содержит закрытые ключи сервера**. Храните его
в доступном только вам месте. Импортируйте только собственные архивы.
Проверки SHA-256 обнаруживают повреждение, но не подтверждают автора архива.

Ключи участников остаются в их приложениях. На новом компьютере отдельно
восстановите свою карточку владельца: сначала проверьте новую ссылку в форме
подключения, затем откройте восстановление карточки. Сам серверный архив
не даёт приложению закрытый ключ владельца. Сохраните карточку заранее.

При смене IP постоянный адрес, используемый в подписях личности, не меняется.
Сервер подписывает связь этого адреса с новым адресом подключения и сохранённым
TLS-отпечатком. Клиент проверяет подпись, ключ сервера и TLS до входа.
Карточки восстановления и история смены ключей продолжают проверяться.
Для этого участникам нужен Space v0.2.5 или новее; runtime — v0.2.4 или новее.

Нельзя держать две импортированные копии одного пространства одновременно
доступными участникам: изменения между ними не синхронизируются. Переносите
пространство после остановки исходного сервера и используйте один экземпляр.

На Android доступны подключение по ссылке, QR через камеру и изображение,
чат и управление доступными пространствами. Создание, запуск и перенос
домашнего сервера доступны только на компьютере.

## Проверка восстановления v0.6

18 октября 2026 года на Windows выполнен `client/tool/home_transfer_drill.dart`
с runtime, собранным из текущих исходников, и PostgreSQL из установленного
комплекта v0.4.2. Использовалось отдельное временное пространство; рабочие
данные установленного приложения не изменялись.

Проверены экспорт остановленного сервера, предварительная проверка архива,
восстановление с новым адресом, прежние server ID, постоянный адрес и TLS,
вход владельца и участника, сообщение, бинарное вложение с проверкой SHA-256,
реакция и её автор, старая карточка владельца и продолжение смены его ключа.
После повторного запуска восстановленного сервера проверены права,
сообщения, вложение, реакция и отсутствие дублей нового сообщения.

Тесты `TestPortableSpaceRoundTrip` и
`TestPortableRestoreFailureDoesNotPublish` выполнены с настоящей PostgreSQL.
Непригодный дамп с корректными хешами не публикует пространство: временная
база удаляется, исходный ZIP не меняется. Успешная предварительная проверка
целостности сама по себе не гарантирует успешного восстановления базы.

Серверный архив не содержит защищённое локальное состояние MLS, ключи
устройств или расшифрованный архив истории клиента. Держите их отдельно.
Проверка выше относится к обычному чату; расшифровка MLS после восстановления
сервера этим сценарием не подтверждена. Восстановление старой серверной копии
при более новом состоянии устройств требует отдельной проверки согласования
MLS; нельзя отключать защиту от отката или сбрасывать её отметки ради входа.

### Дополнительная проверка MLS

18 октября 2026 года `client/test/live/mls_restore_test.dart` прошёл на Windows
с настоящими PostgreSQL и Rust MLS-мостом. Отдельно от серверного ZIP сохранено
состояние трёх независимых устройств в тестовых защищённых хранилищах. После
импорта читается прежнее закрытое сообщение, каждое устройство расшифровывает
вложение 300 КБ с побайтовой сверкой. Проходят смена эпохи, отправка владельцем
и обоими участниками, повторный запуск и повторное чтение файла без дублей.
При повторном импорте старого ZIP сервер отклоняет курсор устройства, который
опережает сохранённую историю. Локальные история и состояние канала не меняются.

Для запуска нужны `SPACE_HOME_RUNTIME` с комплектом PostgreSQL и
`SPACE_RESTORE_EXECUTABLE` с проверяемым сервером; затем из `client` выполните
`flutter test test/live/mls_restore_test.dart`. Без переменных тест пропускается.
Проверка не охватывает восстановление потерянных ключей или перенос хранилища
ключей между ОС. Старый серверный архив не возвращает события, созданные после
его экспорта. Защиту устройства от отката отключать нельзя.
