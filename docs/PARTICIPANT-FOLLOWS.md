# Подписки и персональная лента пространства

Новый срез после v0.7.28 / runtime v0.7.22. Публикация отдельного релиза
в этот срез не входит. Контракт: [ADR-059](https://github.com/space-protocol-project/space-protocol/blob/main/docs/adr/059-participant-follows.md),
capability `core.participant.follows.v1`, схема сервера 41.

## Поведение

В ленте и комментариях рядом с автором доступна подписка. «Моя лента» собирает
публикации, репосты и цитаты выбранных авторов из доступных разделов текущего
пространства в обратном хронологическом порядке. Из записи можно перейти
к исходной публикации и обсуждению. Комментарии не становятся отдельными записями
персональной ленты. Поиск, форум и чаты сохраняют свои обычные представления.

«Подписки» показывает собственный список и позволяет отписаться. Список общий
для устройств участника внутри пространства и закрыт от остальных участников.
Профиль остаётся общим для пространства: актуальное имя и аватар загружаются
через существующий сервис профилей, без переопределений по разделам.

Для недоступного автора список показывает нейтральную подпись без имени.
Отписаться от такого автора можно. Максимум 1000 подписок, страницы по 20 записей
(сервер допускает до 50). Клиент ограничивает открытую персональную ленту
500 записями. Обновление каждые 10 секунд сохраняет загруженный диапазон.

## Доступ и согласованность

Каждый серверный запрос проверяет сессию, grant, членство, блокировку,
включённое общение и `chat.read`. Право публикации не требуется. Подписаться
можно на активного автора видимого содержимого доступного раздела ленты.
Подписка не предоставляет новых прав чтения.

Сервер фильтрует разделы по `visible/read` до ограничения страницы. Архивные
разделы, MLS, скрытые публикации и заблокированные авторы исключаются.
Скрытый оригинал цитаты не раскрывается. Чтение персональной ленты
не создаёт отметок прочтения и уведомлений.

Изменения используют абсолютное состояние и общую ревизию подписок.
Конфликт с другим устройством требует обновления списка. Пагинация привязана
к участнику, типу выдачи и ревизии; права проверяются заново на каждой странице.
Смена пространства, личности, grant, каталога или ошибка страницы очищает
устаревшие данные. Переход к оригиналу повторно проверяется обычным FeedService.

## Проверки

Генерация контракта и Freezed, анализ, тесты, COG и платформенные сборки
выполняются в GitHub CI. Сквозной сценарий использует настоящий Dart/Connect,
Go и отдельную PostgreSQL, проверяет приватность, отзыв доступа и сохранение
подписок после штатной остановки и перезапуска. Нативный сценарий Linux
проверяет кнопки, переход к оригиналу и горячий перезапуск с тестовым API;
он дополняет серверную проверку. Локальные сборки, тесты, Android-устройство
и эмулятор не используются.
