# Вложения, лимиты хранилища и ники

## Поведение

Вложения добавляются кнопкой или перетаскиванием файлов в чат. Сначала показывается список выбранных файлов. При отправке файлы загружаются последовательно с прогрессом, отменой и повтором после ошибки. Повтор использует прежние ключи загрузки и сообщения. Разрешены сообщения только с файлами. В переписке показываются название, размер и скачивание. В «Моих файлах» текущего канала показаны собственные опубликованные файлы, сгруппированные по местной дате.

По умолчанию: до пяти файлов в сообщении, 20 МиБ на файл, 1 ГиБ на сервер и 1 ГиБ на участника. Общий и стандартный личный лимиты меняются в управлении пространством. В карточке участника владелец может задать индивидуальный лимит; пустое поле возвращает стандартный. Значения задаются в МиБ, от 0 до 1048576. Ноль запрещает новые загрузки. Уменьшение лимита не удаляет уже загруженные файлы. Лимиты учитывают весь заявленный размер незавершённых загрузок.

Необязательный ник задаётся при подключении и сохраняется на сервере. В карточке он отображается над идентификатором; поиск участников учитывает ник. Ник не заменяет идентификатор и не обязан быть уникальным.

## Хранение и протокол

Схема PostgreSQL 13. Метаданные и части файлов хранятся в `assets` и `asset_chunks`; существующие операции резервного копирования и переноса базы включают их. `storage_group` — логическая группа `principal_id/YYYY/MM/DD` по UTC, а не каталог файловой системы. В сообщении хранится снимок метаданных вложений для истории, событий и локального кэша.

ConnectRPC AssetService: BeginUpload, UploadChunk, CompleteUpload, CancelUpload, DownloadChunk, ListMyAssets. Части — 256 КиБ; увеличенный лимит тела применяется только к UploadChunk. Остальные запросы остаются ограничены 16 КиБ. Завершение проверяет полный размер, SHA256 и определяет MIME по содержимому. Скачивание в приложении повторно проверяет SHA256 перед системным диалогом сохранения. Файлы автоматически не открываются. Существующий лимит переносимого архива (2 ГиБ) не изменён; увеличение файловых квот не увеличивает этот предел.

Сервер проверяет текущую сессию, права канала и владельца загрузки. Публикация сообщения и связывание готовых вложений выполняются одной транзакцией. Удаление сообщения удаляет его файлы и освобождает место. Незавершённые и неиспользованные загрузки старше суток очищаются при следующей новой загрузке. Дополнительно ограничены число файлов на сервере (10000) и число неподключённых загрузок участника (20). Антивирусная проверка и превью содержимого не реализованы.

## Проверки

- Сервер: реальные PostgreSQL и ConnectRPC; размер и имена, повторы частей и запросов, SHA256, публикация, история, скачивание, удаление, общий/личный/индивидуальный лимиты, доступ после смены ACL, сохранение ника.
- Приложение: размер и число файлов, загрузка частями, повтор после сетевой ошибки, отмена во время RPC, проверка скачанного SHA256; перетаскивание в интерфейс на ширине 390 и 1100, пять выбранных файлов и клавиатура.
- Итоговые локальные проверки: `flutter analyze`, 303 теста приложения (5 штатных пропусков), `flutter build windows --release`, `flutter build apk --release`; серверные `go test ./...` с PostgreSQL, дополнительные тесты ACL/квот и `go vet ./...` проходят. Android собран; ручное сохранение файлов на телефоне не проверено — устройство не подключено.
- Аудит когнитивной сложности: рабочие функции приложения и сервера не выше COG 15.

Нужны обновлённые приложение и сервер: старый runtime v0.2.5 не реализует новые RPC. Выпуск и публикация этих изменений пока не выполнялись.

### Сквозная проверка v0.3 с настоящим сервером

На Windows из корня space-app:

```powershell
./tools/check_attachments.ps1 -DatabaseUrl $env:SPACE_TEST_DATABASE_URL -PostgresBin $env:SPACE_TEST_POSTGRES_BIN -OutputDirectory $env:TEMP
```

Нужна отдельная работающая локальная PostgreSQL, `psql.exe`, Go/Flutter и checkout space-server рядом с space-app. Команда собирает настоящий сервер, создаёт уникальную схему `space_v03_<случайный идентификатор>`, запускает сервер на свободных loopback-портах и проверяет два настоящих Dart-клиента. После проверки сервер останавливается, созданная схема удаляется, журналы сохраняются в указанной папке. Файлы теста создаются в системном временном каталоге и удаляются отдельно после завершения.

Проверены необязательный ник, файл больше одной части (256 КиБ + 31 байт), доставка метаданных через Subscribe, повтор CreateContent без дубля, скачивание с проверкой SHA256, повторный вход с прежней идентичностью, история, удаление и очистка списка файлов. Первый запуск обнаружил предел 16 КиБ во внутреннем gRPC-мосте; он исправлен. Unary и streaming interceptors сохраняют предел 16 КиБ для обычных методов, увеличенный предел действует только для UploadChunk. Добавлены отдельные проверки ограничений.

Результат 15 октября 2026: сквозной сценарий проходит. Android-приёмка отложена пользователем; закрывать этот пункт автоматически нельзя. Обычный `flutter test` пропускает живой серверный тест без `SPACE_ATTACHMENTS_TEST_ORIGIN`; команда выше запускает его с нужным окружением.
