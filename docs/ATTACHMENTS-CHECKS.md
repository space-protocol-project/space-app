# Вложения, лимиты хранилища и имена

## Поведение

Вложения добавляются кнопкой или перетаскиванием файлов в чат. Сначала показывается список выбранных файлов. При отправке файлы загружаются последовательно с прогрессом, отменой и повтором после ошибки. Повтор использует прежние ключи загрузки и сообщения. Разрешены сообщения только с файлами. В переписке показываются название, размер и скачивание. В «Моих файлах» текущего канала показаны собственные опубликованные файлы, сгруппированные по местной дате.

По умолчанию: до пяти файлов в сообщении, 20 МиБ на файл, 1 ГиБ на сервер и 1 ГиБ на участника. Общий и стандартный личный лимиты меняются в управлении пространством. В карточке участника владелец может задать индивидуальный лимит; пустое поле возвращает стандартный. Значения задаются в МиБ, от 0 до 1048576. Ноль запрещает новые загрузки. Уменьшение лимита не удаляет уже загруженные файлы. Лимиты учитывают весь заявленный размер незавершённых загрузок.

Необязательное имя задаётся при подключении и сохраняется на сервере. В карточке оно отображается над идентификатором; поиск участников учитывает имя. Имя не заменяет идентификатор; уникальность проверяется сервером при сохранении.

## Хранение и протокол

Схема PostgreSQL 14 (файлы добавлены миграцией 13, разрешение вложений — миграцией 14). Метаданные и части файлов хранятся в `assets` и `asset_chunks`; существующие операции резервного копирования и переноса базы включают их. `storage_group` — логическая группа `principal_id/YYYY/MM/DD` по UTC, а не каталог файловой системы. В сообщении хранится снимок метаданных вложений для истории, событий и локального кэша.

ConnectRPC AssetService: BeginUpload, UploadChunk, CompleteUpload, CancelUpload, DownloadChunk, ListMyAssets. Части — 256 КиБ; увеличенный лимит тела применяется только к UploadChunk. Остальные запросы остаются ограничены 16 КиБ. Завершение проверяет полный размер, SHA256 и определяет MIME по содержимому. Скачивание в приложении повторно проверяет SHA256 перед системным диалогом сохранения. Файлы автоматически не открываются. Существующий лимит переносимого архива (2 ГиБ) не изменён; увеличение файловых квот не увеличивает этот предел.

Сервер проверяет текущую сессию, права канала и владельца загрузки. Публикация сообщения и связывание готовых вложений выполняются одной транзакцией. Удаление сообщения удаляет его файлы и освобождает место. Незавершённые и неиспользованные загрузки старше суток очищаются при следующей новой загрузке. Дополнительно ограничены число файлов на сервере (10000) и число неподключённых загрузок участника (20). Антивирусная проверка и превью содержимого не реализованы.

## Проверки

- Сервер: реальные PostgreSQL и ConnectRPC; размер и имена, повторы частей и запросов, SHA256, публикация, история, скачивание, удаление, общий/личный/индивидуальный лимиты, доступ после смены ACL, сохранение имени.
- Приложение: размер и число файлов, загрузка частями, повтор после сетевой ошибки, отмена во время RPC, проверка скачанного SHA256; перетаскивание в интерфейс на ширине 390 и 1100, пять выбранных файлов и клавиатура.
- Итоговые локальные проверки: `flutter analyze`, 330 тестов приложения (6 штатных пропусков), `flutter build windows --release`, `flutter build apk --release`; серверные `go test ./...` с PostgreSQL, дополнительные тесты ACL/квот и `go vet ./...` проходят. Android собран; ручное сохранение файлов на телефоне не проверено — устройство не подключено.
- Аудит когнитивной сложности: рабочие функции приложения и сервера не выше COG 15.

Нужны обновлённые приложение и сервер: старый runtime v0.2.5 не реализует новые RPC. После установки приложения v0.3.0 обновите сервер через «Эфир → Обновить сервер». Существующие файлы и сообщения сохраняются при обновлении.

### Сквозная проверка v0.3 с настоящим сервером

На Windows из корня space-app:

```powershell
./tools/check_attachments.ps1 -DatabaseUrl $env:SPACE_TEST_DATABASE_URL -PostgresBin $env:SPACE_TEST_POSTGRES_BIN -OutputDirectory $env:TEMP
```

Нужна отдельная работающая локальная PostgreSQL, `psql.exe`, Go/Flutter и checkout space-server рядом с space-app. Команда собирает настоящий сервер, создаёт уникальную схему `space_v03_<случайный идентификатор>`, запускает сервер на свободных loopback-портах и проверяет два настоящих Dart-клиента. После проверки сервер останавливается, созданная схема удаляется, журналы сохраняются в указанной папке. Файлы теста создаются в системном временном каталоге и удаляются отдельно после завершения.

Проверены необязательное имя, файл больше одной части (256 КиБ + 31 байт), доставка метаданных через Subscribe, повтор CreateContent без дубля, скачивание с проверкой SHA256, повторный вход с прежней идентичностью, история, удаление и очистка списка файлов. Первый запуск обнаружил предел 16 КиБ во внутреннем gRPC-мосте; он исправлен. Unary и streaming interceptors сохраняют предел 16 КиБ для обычных методов, увеличенный предел действует только для UploadChunk. Добавлены отдельные проверки ограничений.

Результат 15 октября 2026: сквозной сценарий проходит. Android-приёмка отложена пользователем; закрывать этот пункт автоматически нельзя. Обычный `flutter test` пропускает живой серверный тест без `SPACE_ATTACHMENTS_TEST_ORIGIN`; команда выше запускает его с нужным окружением.

### Правая панель вложений

При ширине области чата от 1080 px справа появляется панель шириной 320 px со скруглённым фоном. Высота равна содержимому до нижней границы области чата, затем список прокручивается. Список также открывается пунктом «Вложения чата» в левой боковой панели; на телефоне — в меню навигации. Пункт «Мои файлы» расположен там же. Кнопка прикрепления «+» находится внутри поля сообщения; выбранные файлы, прогресс и отмена остаются над полем. Список показывает опубликованные вложения всех участников текущего канала, группирует их по локальным датам и фильтрует по автору. Отображается имя, а при его отсутствии — идентификатор. Фильтр использует идентификатор участника; имя не заменяет его идентичность.

ListChannelAssets проверяет действующую сессию и право чтения канала; выдаёт страницы по 50 файлов и список авторов опубликованных вложений. Собственный ListMyAssets сохраняет прежнее ограничение автором. Новые сообщения и удаления обновляют открытую боковую панель; есть ручное обновление. Запоздалый ответ предыдущего фильтра игнорируется.

Предыдущая пара app 34d9d08 / server 0d7dbdf прошла все CI: приложение Windows/macOS/Linux/Android (38668604621), сервер (38668612524), runtime Windows/macOS/Linux с обновлением/восстановлением/переносом (38668614869). Правая панель включена в итоговые 330 тестов приложения.

Проверки панели: фильтр и страницы, игнорирование запоздалых ответов, ширины 280/480 px, автоматическое появление на широком окне 1500 px, компактная высота и прокрутка длинного списка. Новый RPC проверен настоящими Dart-клиентами через ConnectRPC; Go-проверка закрытого канала подтверждает запрет списка до выдачи права чтения и после его отзыва. Для HTTP 415 показано требование актуального сервера вместо сырого исключения.

### Смена собственного имени

В «Обзоре» выбранного сервера показано поле «Свое имя в этом пространстве». Актуальный контракт профиля описан в [PARTICIPANT-PROFILES.md](PARTICIPANT-PROFILES.md): GetParticipantProfile и UpdateParticipantProfile заменяют прежнее изменение ника. Сервер сравнивает непустые имена по Unicode NFKC/case folding, исключая самого автора, и удерживает общую транзакционную блокировку до сохранения. Это защищает также от двух одновременных назначений одного имени. Ранее сохранённые имена автоматически не переименовываются. При совпадении возвращается AlreadyExists, введённый текст остаётся в форме. Уникальность действует внутри одного сервера, пустое имя освобождает имя. Проверки включают кириллицу, китайский, совместимые Unicode-формы, конкурентный захват и два настоящих Dart-клиента через ConnectRPC. Для проверки уникальности требуется обновлённый сервер.

Поле сообщения: текст занимает верхнюю часть, «+» и отправка расположены отдельным нижним рядом. Начальная высота рассчитана на три строки; поле растёт до трети высоты окна и затем прокручивает текст внутри. Проверены расположение кнопок, предел высоты, прокрутка, имитация отступа экранной клавиатуры и режим без права отправки в widget-тестах. «Мои файлы» не показывает сырой HTTP 415 и кнопку следующих страниц при ошибке: выводятся сообщение об актуальном сервере и обновление списка. Тест повторной загрузки подтверждает восстановление после ошибки.

### Разрешение вложений для отдельного сервера

Настройка «Разрешить вложения файлов» доступна владельцу/администратору; по умолчанию включена. Миграция 14 сохраняет её в space_settings. Manifest задаёт начальную политику, WatchChannels доставляет изменения подключённым участникам. Каждый SpaceSession хранит свою политику: настройка одного сервера не меняет другой. При запрете скрыты прикрепление, drag&drop, файловые разделы, правая панель и метаданные вложений в пользовательском представлении истории; сохранённые файлы остаются на сервере. Чистый текст можно отправлять. Сервер запрещает новые загрузки, части, завершение, публикацию вложений, списки и скачивание. Повторное включение возвращает функции и сохранённые вложения. Проверены независимость двух контроллеров пространств, скрытие элементов на 390/1100/1500 px, сохранение настройки администратором и доставка изменения двум настоящим ConnectRPC-клиентам.
