# Потоковые архивы Android

## Ограничения и полномочия

Большой полный архив устройства `.spacedevice` проходит через системный SAF:
`ACTION_OPEN_DOCUMENT` для чтения, `ACTION_CREATE_DOCUMENT` для нового документа.
Общего доступа к накопителю нет. В Dart передаются состояние, счётчик байтов
и приватный путь, но не содержимое архива. Kotlin копирует блоками по 64 КиБ
в фоновом потоке, с обратным давлением и счётчиком `Long`.

Верхняя граница — 2199912448 байт (2 ГиБ + 50 МиБ), тот же внешний предел,
который уже принимает `MigrationArchive`. Размер от провайдера не считается
доверенным: предел проверяется по реально прочитанным байтам до записи блока.
Пустой документ отклоняется. Импорт сначала полностью копируется в приватный
файл; только затем существующий валидатор проверяет формат, пароль, все блоки,
подписи, размеры распаковки и пригодность установки. Доступ из файла не выдаётся.
Формат и криптографические алгоритмы не меняются. Небольшие recovery JSON/PNG
и каталог `.spacebackup` сохраняют свои отдельные пределы.

На диске требуется место под зашифрованную копию и существующие временные
файлы проверки/распаковки. Ошибка места, сети или провайдера завершает копирование
ошибкой. Операция не запускает службу в фоне: после уничтожения процесса
копирование начинается заново, а не продолжается с недоверенного смещения.

## Отмена и критическая граница

При выборе документа и потоковом копировании доступна отмена. Она сигнализирует
нативной операции, закрывает открытые дескрипторы и ждёт завершения очистки.
Поздний результат системного диалога не начинает отменённое копирование.
Пока диалог или рабочая операция не завершены, новая операция не начинается.
Системный провайдер может задержать обработку закрытия/отмены; жёсткий срок
завершения произвольного облачного провайдера не обещается.

После начала подготовки полного экспорта или применения импорта отмена
блокируется до возврата существующего механизма переноса: принудительное
прерывание могло бы оставить остановленные исходные ключи либо частичный импорт.
Интерфейс показывает эту границу. Ошибка применения сохраняет исходный архив
для повтора. Пароль не сохраняется.

## Сохранность и очистка

Одновременно хранится один незавершённый перенос в `noBackupFilesDir` приложения.
Состояние записывается атомарно; имена локальных файлов фиксированы, пути из
канала не принимаются. Неполный импорт `.part` удаляется при ошибке, отмене
и следующем открытии моста. Исходный выбранный документ никогда не удаляется.

Подготовленный экспорт и его `.pending` не являются мусором: после остановки
источника они могут быть единственной копией ключей. Они сохраняются после
отмены, ошибки и перезапуска. Экран предлагает повтор подготовки/сохранения.
Приватный готовый экспорт остаётся доступен для повторного сохранения даже
после успешного экспорта; удалить его можно только отдельной явной командой.
Начатый импорт аналогично сохраняется до успешного применения; отказ до начала
применения разрешает удалить только принадлежащую приложению копию.

Перед записью нового SAF-документа его URI записывается в журнал очистки.
При ошибке/отмене удаляется только этот созданный документ. Если провайдер
отказывает в удалении, операция сообщает об этом, запись сохраняется для повтора
при следующем запуске. Без сохраняемого разрешения после потери процесса удаление
может потребовать ручной очистки у провайдера; интерфейс не сообщает об успехе.
После закрытия потока сохранённый документ читается повторно блоками и сверяется
по размеру и SHA-256, прежде чем он считается записанным. Это не гарантия
долговечности стороннего облачного хранилища при его собственном сбое.

Удаление приватных копий не обещает физического стирания флеш-памяти.
Незашифрованные рабочие ключи, пароль, содержание архива и URI не попадают в логи.

## Проверки

Только GitHub CI: Dart-анализ и COG, тесты Cubit и канала, существующие проверки
миграции, Kotlin-тесты ограниченного потока, APK и Android-эмулятор с настоящим
ContentResolver/тестовым DocumentsProvider. Проверяются большие и неизвестные
размеры, короткие чтения, отмена, отказ записи/удаления, повтор после перезапуска
и сохранение единственного экспорта. Физическое устройство не требуется.

Основания: [SAF](https://developer.android.com/training/data-storage/shared/documents-files),
[CancellationSignal](https://developer.android.com/reference/android/os/CancellationSignal).
