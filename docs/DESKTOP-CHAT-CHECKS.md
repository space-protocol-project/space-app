# Проверка десктопного чата после v0.4.2

Дата: 17 октября 2026 года. Локальная платформа: Windows. Эмулятор и физический Android не использовались. Личные пространства и настройки пользователя не менялись.

## Выпущенная база и найденное исправление

Совместимая пара v0.4.2 со схемой PostgreSQL 22 опубликована. Её релизные проверки: [приложение](https://github.com/space-protocol-project/space-app/actions/runs/39017978687), [runtime](https://github.com/space-protocol-project/space-server/actions/runs/39017249253).

При проверке настоящего окна обнаружено различие интерфейса: в MLS были видны маркеры `**жирного текста**`, время стояло слева под реакциями. В исходниках после v0.4.2 подключены общие MessageMarkdown, MessageBodyLayout и MessageFooter. Время теперь справа в одной нижней строке с реакциями, сверху есть отступ. Шифрование, доставка и формат сообщений не менялись. Это исправление ещё не выпущено. Новая Windows Debug-сборка собрана; при холодном запуске дерево доступности содержит форматированный заголовок MLS без Markdown-маркеров. История повторно прочитана из runtime и сохранённого тестового состояния MLS.

Исправление отправлено коммитом `6537a74`; в `9cfa2a4` отдельные тесты Markdown и MLS-раскладки включены в каждую настольную платформу CI. [Итоговый CI 39020515483](https://github.com/space-protocol-project/space-app/actions/runs/39020515483) успешен на Windows/macOS/Linux и при сборке Android. [MLS CI 39020299229](https://github.com/space-protocol-project/space-app/actions/runs/39020299229) также успешен. Изменения плана отправлены в протоколе `6e459c7`, [CI 39020303350](https://github.com/space-protocol-project/space-protocol/actions/runs/39020303350) успешен. Предыдущий прогон установщиков 39020299437 отменён как заменённый; он не считается успешной проверкой.

## Что остаётся открытым

- Полная ручная проверка мышью и клавиатурой в установленном приложении Windows: автоматизация окна получала отказ активации, затем предупреждение о пользовательском вводе. Успех чтения дерева доступности не считается успехом ввода.
- При горячем перезапуске проверочной оболочки Flutter сообщил об ошибках обновления AXTree; дерево доступности осталось от прежней вкладки, хотя снимок показал MLS. Это наблюдение режима разработки, а не доказанная ошибка холодного запуска опубликованного установщика.
- Фактическое нажатие системной карточки и полный цикл обновления установленного приложения на Windows/macOS/Linux. Релизный CI и локальные тесты не закрывают все пользовательские окружения.
- Android service, Doze, перезагрузка и системная карточка: не запускались по указанию пользователя.

Milestone v0.5 остаётся открытым для платформенной приёмки. Временные базы, ключи тестовых личностей и оболочка находятся в исключённых из Git локальных каталогах; в репозиторий не добавляются.

## Следующий срез v0.5: интерфейс и настоящий сервер в одном тесте

Добавлен `client/test/live/desktop_chat_server_test.dart`. В одном сценарии настоящие ChatView и MlsChannelView отправляют сообщения через поле ввода, открывают меню правой кнопкой мыши, отвечают и ставят реакцию. Второй клиент проверяет сохранённые в PostgreSQL обычные сообщения и расшифрованные MLS-сообщения, цель ответа и реакцию. Затем новый сеанс и новый MLS-клиент читают прежнее тестовое состояние без создания нового ratchet.

Это автоматический тест Flutter на Windows с настоящими HTTP/RPC, PostgreSQL и Rust MLS; он не управляет окном установленного приложения и не заменяет ручную платформенную приёмку. Хранилище тестовых ключей и очереди находится в памяти. Восстанавливается сеанс/клиент, а не весь процесс ОС; отдельные проверки постоянного хранилища остаются обязательными.

Локальный результат: один объединённый сценарий успешно завершился за семь секунд. Проверяются не только тексты, но и идентификатор исходника обычного ответа, зашифрованная ссылка MLS-ответа, участник обычной реакции и отсутствие дублей сообщений при повторном открытии MLS-клиента.

Запуск из корня приложения при заданных `SPACE_TEST_DATABASE_URL` и `SPACE_TEST_POSTGRES_BIN` для отдельной локальной PostgreSQL:

```powershell
. ./tools/mls_environment.ps1
./tools/check_attachments.ps1 -Scenario desktop
```

Рядом нужен checkout `space-server` и установленный Go. Сценарий создаёт отдельную случайную схему, запускает свой сервер на свободных loopback-портах, сверяет server ID с созданной схемой и удаляет только свою схему при завершении. Прямой запуск теста без `SPACE_DESKTOP_CHAT_TEST_ORIGIN` даёт явный пропуск; небезопасный нелокальный адрес отклоняется до соединения. В workflow установщиков добавлено обязательное задание «Интерфейс чата и отдельная PostgreSQL» на Windows. Оно берёт исходники проверенного runtime v0.4.2 на коммите c87ac2a и PostgreSQL из закреплённого manifest с проверкой размера/SHA-256, создаёт отдельный кластер и случайную схему. Сервер и PostgreSQL останавливаются в finally; копия тестового сервера и скачанный архив удаляются. Журналы сохраняются в артефакте desktop-chat-logs на семь дней. Выпуск установщиков зависит от успеха этого задания.

В обязательном задании выставляется SPACE_REQUIRE_DESKTOP_CHAT_TEST=1: отсутствие адреса runtime завершает проверку ошибкой вместо пропуска. В обычном запуске тестов без тестового окружения явный пропуск сохраняется. Это проверка Flutter-интерфейса и настоящего сервера; ручная приёмка установленного приложения и системных карточек остаётся открытой.

Скрипты PowerShell с русскими сообщениями сохранены в UTF-8 с BOM для совместимости с Windows PowerShell 5.1. `tools/clean_unused_builds.ps1` по умолчанию показывает план без удаления; `-Apply` очищает только перечисленные артефакты с проверкой путей и ссылок, сохраняя два последних снимка компиляции.
