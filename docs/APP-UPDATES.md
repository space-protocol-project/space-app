# Простое обновление приложения

Обновления проверяются при запуске и в настройках. Приложение получает выпуск
из `space-protocol-project/space-app`, выбирает пакет для своей ОС/архитектуры
и загружает его с процентами и докачкой. Обязательны размер и SHA-256 из
GitHub Releases. По решению владельца от 13 октября 2026 года ключи и
подписанный манифест для этого механизма не используются; секреты CI не нужны.

В установленной Windows-копии после загрузки доступна кнопка
«Установить и перезапустить». Приложение повторно проверяет файл, ждёт
завершения текущих операций, штатно останавливает свой домашний сервер и
PostgreSQL и только затем запускает Inno Setup отдельным процессом.
Неподтверждённые сообщения, занятый домашний сервер и отказ остановки
блокируют установку. Ошибка запуска оставляет приложение открытым.

Установщик получает существующий каталог приложения и постоянный AppId;
профили, защищённое хранилище и домашние данные остаются в прежних внешних
каталогах. Журнал находится в каталоге поддержки приложения `updates/install.log`.
После успешной установки новый установщик запускает Space по `/RELAUNCH`.
Прежние подключения восстанавливаются существующим механизмом профилей;
если домашний сервер работал, приложение предлагает запустить его снова.

В копии из каталога сборки кнопка установки отсутствует: используйте
«Открыть выпуск». На macOS/Linux пока доступны загрузка и страница выпуска;
автоматическая замена установленного приложения остаётся отдельной задачей.

Параметры Inno Setup:
[официальная документация](https://jrsoftware.org/ishelp/topic_setupcmdline.htm).
`/RELAUNCH` — наш дополнительный параметр, обработанный в `windows.iss`.

Опубликованные v0.2.1 не изменялись. Новый номер не назначен и выпуск не создан.
Модульные проверки заменяют запуск процессов подставными функциями. Отдельный
сценарий Windows CI устанавливает публичный v0.2.1 в каталог с пробелами,
запускает и закрывает прежнее приложение, затем вызывает настоящий AppUpdates
с пакетом из текущей сборки CI. Проверяются фактическая замена бинарного файла,
перезапуск через /RELAUNCH, прежние AppId/каталог и журнал, сохранение отдельной
записи SharedPreferences, записи системного vault и контрольного файла в
home-server/data. Установщик, который проверяется, содержит основной main.dart;
проверочный процесс собирается отдельно и не попадает в установщик.

Сценарий не запускает домашний сервер/PostgreSQL и не проверяет миграцию базы.
Проверка установки на физической системе пользователя остаётся отдельной
приёмкой перед следующим выпуском. Локально установщик не запускался.
