# Пространство на Linux-сервере без домашнего компьютера

Реализация находится в `main`; публичный v0.3.2 её не содержит.
Команды ниже предназначены для нового выпуска v0.3.3.

Начиная с приложения и runtime v0.3.3. Нужен Linux x64 с glibc,
обычный пользователь (не root), `curl`, `unzip`, `sha256sum` и доступный TCP 8443.
Отдельные Go и PostgreSQL не нужны. Участники могут пользоваться Android.

```sh
curl -fsSL https://raw.githubusercontent.com/space-protocol-project/space-server/v0.3.3/packaging/install.sh | sh
```

Установщик скачивает последний runtime, проверяет SHA-256 и запускает сервер.
При первом запуске внешний IP определяется через ipify. Если нужен домен или
другой внешний порт, передайте адрес явно:

```sh
curl -fsSL https://raw.githubusercontent.com/space-protocol-project/space-server/v0.3.3/packaging/install.sh | sh -s -- -address https://space.example.org:9443 -listen 0.0.0.0:9443
```

1. Разрешите входящий TCP-порт в файрволе сервера и в панели провайдера.
2. Дождитесь ссылки настройки в терминале. Она содержит отпечаток сертификата,
   server ID и одноразовый секрет; действует 15 минут. Не публикуйте ссылку.
3. На компьютере или телефоне откройте Space → подключение, вставьте ссылку,
   проверьте сервер и нажмите кнопку подключения. Первый вошедший по этой ссылке
   становится владельцем. Создавать пространство на своём компьютере не нужно.
4. Создайте приглашение для остальных. В управлении пространством → участники
   выберите роль «Администратор» нужному человеку. Администраторов может быть
   несколько; владелец остаётся один. На дополнительном устройстве право управления
   выдаётся отдельно, обычный grant сам по себе не расширяется.

Сервер работает в текущем терминале; Ctrl+C штатно останавливает его.
Повторный запуск той же команды сохраняет владельца, участников, каналы и данные.
После назначения владельца повторная ссылка настройки не выдаётся. Если 15 минут
истекли до первого входа, перезапустите сервер — старая ссылка станет недействительной.

Данные: `~/.local/share/space-server/home/data`; сеть: `home/config.json`.
Runtime хранится отдельно в `runtimes/<версия>`. `SPACE_HOME` меняет общий каталог,
`SPACE_VERSION=v0.3.3` закрепляет версию скачивания. Каталоги старых runtime
установщик не удаляет. Для последующих запусков без скачивания используйте:

```sh
~/.local/share/space-server/runtimes/v0.3.3/space-server start -data ~/.local/share/space-server/home
```

При существующей конфигурации сервер использует сохранённые адреса. Их можно
менять через `home/config.json` при остановленном сервере; поддерживаются несколько
адресов, домен и IPv6. За CGNAT нужен публичный адрес или туннель. Настройка NAT,
автозапуск/systemd, контейнерный образ и relay остаются отдельными задачами.

Защита первого входа: публично доступно подписанное discovery, но RPC настройки
требуют одноразовый секрет поверх закреплённого TLS. До завершения настройки
доступны только manifest, challenge, регистрация/вход и атомарный ClaimOwner.
После ClaimOwner сервер закрывает свободную регистрацию перед открытием обычного
входа. Секрет удаляется из RPC-соединения клиента и не записывается в его vault.
