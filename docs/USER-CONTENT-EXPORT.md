# Экспорт собственного содержимого

В «Моём устройстве» выберите идентичность нужного пространства и откройте
«Экспорт моего содержимого». Выберите раздел и при необходимости даты UTC,
нажмите «Подготовить JSON», затем «Сохранить JSON». Пустой период означает
всю доступную историю; конечная дата в интерфейсе включается целиком.

В документ входят собственные обычные сообщения, темы и ответы форума, публикации
и комментарии ленты из доступных неархивных разделов. Нужны действующая сессия,
членство, `chat.read` и серверные visible/read ACL; право записи не требуется.
Скрытые родители исключают ответы. Чужие публикации не копируются в репост:
остаётся только ссылка `repostOf`. MLS исключён из серверного экспорта.

Вложения представлены метаданными: ID, имя, MIME, размер и SHA-256. Бинарные
файлы не включаются. Ключи, токены, настройки сервера и данные чужих профилей
в экспорт не входят. Это самостоятельный документ, не резервная копия
пространства и не формат восстановления устройства.

## Ограничения

Один запрос возвращает до 5000 записей и до 8 МиБ protobuf JSON за пять секунд.
При превышении сервер возвращает ошибку без частичного результата. Выберите
меньший период либо раздел и сохраните несколько файлов. Клиентский JSON
с отступами дополнительно ограничен 16 МиБ. Интерфейс не обрезает данные молча.

Сервер удерживает блокировки проверки прав на протяжении чтения. Экспорт
не меняет непрочитанное и уведомления. Смена контекста или отзыв доступа
во время подготовки очищает результат; ошибка подготовки не создаёт файл.
Уже полученные байты не отзываются при последующем изменении прав.

На Android используется системный `ACTION_CREATE_DOCUMENT`: приложение получает
доступ только к выбранному новому JSON-документу, без общего разрешения на накопитель.
Данные записываются через ContentResolver в отдельном потоке. На настольных ОС
сначала полностью записывается временный файл в каталоге назначения, затем
заменяется выбранный файл. Ошибка записи показывается пользователю с возможностью
повтора; удаление неудавшегося нового Android-документа выполняется по возможности.

## Формат space.user-content, версия 1

UTF-8 JSON без BOM. Верхний объект содержит `format`, `version`, `selection`,
`content`, `attachmentPayloads: false`, `mlsIncluded: false`.

`selection` и `content` используют protobuf JSON из
[user_export.proto](https://github.com/space-protocol-project/space-protocol/blob/main/protocol/proto/space/v1/user_export.proto).
Поля имеют camelCase, int64 представлены десятичными строками, SHA-256 вложения —
Base64, отсутствующие поля имеют значения protobuf по умолчанию. Текст
Markdown сохраняется в исходном виде; никакой HTML не исполняется.

`content` содержит `formatVersion: 1`, `serverId`, собственный `principalId`,
`generatedAtUnixMs` и массив `entries`. Записи упорядочены по времени,
типу, ID раздела и ID объекта (возрастание). У каждой записи есть тип из
`SpaceSearchKind`, ID, раздел, родитель, собственный текст, ревизия, время
в миллисекундах UTC и метаданные вложений. Заголовок присутствует у собственной
темы; чужие заголовки родителей ответов не копируются. Время 0 означает,
что историческое время не известно. Экспорт не включает идемпотентные ключи.

Сервер формирует один ограниченный результат, а не несогласованные страницы.
Файл отражает доступные данные во время запроса. Контракт и проверки прав:
[ADR-060](https://github.com/space-protocol-project/space-protocol/blob/main/docs/adr/060-user-content-export.md).

## Проверки

Go/PostgreSQL проверяют владельца, закрытые разделы, скрытых родителей,
MLS, отзыв сессии/grant/scope, фильтры и отказ вместо усечения. Flutter
проверяет формат, чужие ответы, смену контекста, повтор сохранения и узкий экран.
Отдельный Dart/Connect-сценарий сохраняет JSON, отзывает доступ и перезапускает
настоящий сервер. Нативный Linux-сценарий пишет JSON-файл и выполняет горячий
перезапуск с тестовым API; системный диалог выбора файла в нём заменён
предопределённым тестовым путём. Физический Android и эмулятор не используются.
