# Структурированные упоминания в закрытых чатах

Подготовлено для приложения v0.7.25+55 с совместимым runtime v0.7.19.
Публикация ожидает завершения релизного CI. Схема БД 36 и голосовой профиль 3
сохранены; новый runtime для этого среза не требуется.

Выберите участника через `@` или кнопку упоминания. Имя и постоянный ID
адресата сохраняются внутри MLS-шифротекста вместе с диапазоном UTF-16.
Просто набранное `@имя` остаётся текстом. Можно выбрать до десяти фрагментов;
одинаковые имена различаются по ID. Значок `@` у сообщения показывает
адресатов, обращение к себе выделено цветом. Markdown продолжает работать.

Выбранные обращения сохраняются в защищённом черновике отдельно для каждого
профиля и группы, в очереди отправки, истории, ответах, локальном поиске и
зашифрованном архиве. Изменение имени снимает его привязку; изменение текста
перед именем сдвигает диапазон. Поздняя загрузка или отправка не стирает новый
ввод и не переносит выбор в другой профиль.

Новый формат v2 отправляется только после подтверждения поддержки всеми
устройствами группы по подписанным листьям MLS. Если есть прежнее устройство,
появится пояснение: будет отправлено зашифрованное имя в формате v1 без
структурированной отметки. Для существующего устройства поддержка включается
обычным подтверждённым обновлением листа; приглашать его заново не нужно.
Откат приложения после получения v2 требует совместимой резервной копии и
подходящей версии приложения.

Состав группы проверяется перед отправкой. Если выбранный участник исключён,
отправка останавливается, черновик сохраняется. При остановившемся повторе
после изменения состава откройте «Защита и история» → «Отменить отложенные
отправки после смены состава» и исправьте обращение. Это удаляет только очередь
повторов после смены эпохи; неподтверждённые исходящие пакеты не удаляются.

Сервер видит прежний непрозрачный ciphertext. ID и диапазоны не передаются
отдельными полями RPC, не индексируются сервером и не добавляются в серверный
персональный список. Системная карточка работающего клиента получает сведения
об обращении только после локальной проверки и расшифровки. Изменение схемы
БД и новый runtime для этого среза не нужны.

Формат, правила проверки и согласование поддержки:
[ADR-053](../../space-protocol/docs/adr/053-mls-mentions.md).

## Проверки 25 октября 2026

Перед выпуском v0.7.25 повторно проверены Flutter 3.47.8 / Dart 3.13.7:
локальный Flutter совпадает с актуальной официальной веткой stable.
`dart pub outdated --json` не нашёл доступных совместимых обновлений.
Более новые `http2` и `xml` ограничены родительскими пакетами, а
`material_color_utilities` и `test_api` — стабильным Flutter SDK;
несовместимые версии не навязываются через overrides.

Полный Flutter-прогон: 928 успешных тестов, 35 пропусков; прежняя нативная
библиотека проверена отдельно через `SPACE_MLS_LEGACY_LIBRARY`. Анализатор
чистый; проверка 289 файлов и 2803 функций не нашла превышений COG 15,
максимум — 14.

Прошли 37 Rust-тестов ядра, `fmt`, `clippy --all-targets -- -D warnings`,
тесты и clippy моста, совместимость OpenMLS ↔ mls-rs. Для локальной Windows
проверки mls-rs использованы штатные NASM-объекты из закреплённого crate
AWS-LC (`AWS_LC_SYS_PREBUILT_NASM=1`); производственный провайдер libcrux
и параметры его сборки не менялись.

Настоящая библиотека прежнего клиента читает v1 в смешанной группе;
после подтверждённого обновления листа новые устройства обмениваются v2.
Читающий запрос возможностей не меняет revision и snapshot. Подписанный
участником некорректный JSON отвергается до принятия ratchet; повтор той же
ошибочной записи не расходует ключ, следующее правильное сообщение читается.

Три настоящих Dart-клиента, Go и отдельная PostgreSQL проверили отправку,
уведомление, смену root, исключение устройства и повторное шифрование с тем
же ID адресата. Оба сквозных сценария прошли; сервер и база остановлены.
Widget-тесты проверили экран шириной 360 и 1500 px, Markdown, значок адресата,
предупреждение о совместимости, быстрый ввод и одинаковые имена с разными ID.
Закрытие чата сохраняет последний ввод; ещё не загруженный черновик не
стирается. Повреждённый импорт не изменяет защищённое хранилище.

Windows release и Android debug собраны из окончательного кода.
CRC APK и архитектуры всех 34 ELF-библиотек проверены; MLS-модуль присутствует
для ARMv7, ARM64 и x86_64. Для Windows проверены PE x64 приложения и моста.
Установка и запуск Android на устройстве или эмуляторе не выполнялись;
релизный CI macOS/Linux для нового среза ещё не запускался.

Изолированный Windows debug-стенд создал группу, проверил возможности,
зашифровал сообщение v2 нативным мостом и отобразил Markdown со значком
обращения. Hot reload через Dart MCP успешен, ошибок выполнения до и после
него нет. Ключи и сообщения стенда находились только в памяти; рабочие
профили и серверы не использовались. Стенд после проверки закрыт.
