# Диск и резервные копии

В панели домашнего сервера «Эфир» откройте «Диск и резервные копии» и нажмите
«Показать размеры / обновить». Приложение показывает объём данных пространства,
установленных runtime, резервных копий, данных восстановления и свободное место
на диске сервера. Это логические размеры файлов, без учёта сжатия файловой системы
и размера выделенных блоков. Во время работы сервера значения могут меняться.

## Очистка

1. Остановите сервер. Очистка сериализована с запуском, обновлением и переносом
   через `process.lock`; занятое другим процессом пространство не очищается.
2. Обновите список, отметьте ненужные каталоги и нажмите «Удалить выбранное».
   Для кандидатов показаны относительный путь, размер и дата изменения.
3. Подтвердите удаление в отдельном окне. Перед удалением приложение заново
   проверяет состояние пространства, состав и размеры выбранных каталогов.
   Изменившийся список требует нового просмотра.

Защищены от очистки:

- текущий и предыдущий runtime; без подтверждённого успешного обновления
  старые runtime не предлагаются;
- три самые новые **проверенные** резервные копии и копия из текущего журнала
  обновления/восстановления;
- любые копии моложе 30 дней, неизвестные или повреждённые копии;
- действующие данные пространства, каталог `recoveries`, конфигурация,
  клиентские ключи MLS, внешние ZIP-файлы и нераспознанные каталоги.

Копии в `backups/update-…` проверяются по полному составу и SHA-256 перед
включением в список. Корректность хешей не гарантирует восстановимость PostgreSQL.
Политика фиксированная: три новые проверенные копии плюс минимум 30 дней хранения.
Автоматическое удаление резервных копий и создание копий по расписанию не включены.
Ранее существовавшая очистка runtime после успешного обновления сохраняется.

Ссылки и junction не обходятся. Удаление ограничено распознанными прямыми
потомками `runtimes` и `backups`; рекурсивное удаление с переходом по ссылкам
не используется. При незавершённом или повреждённом журнале очистка запрещена.
Повторная проверка выбранного списка происходит до первого удаления. Если диск
или права доступа изменились уже во время удаления, операция останавливается;
часть выбранных устаревших файлов могла быть удалена. Защищённые копии сохраняются.

## Проверка свободного места

Существующая проверка обновления учитывает резервные копии данных, скачивание,
распаковку runtime и запас 256 МиБ. Дополнительно:

- экспорт проверяет диск сервера для временного дампа и диск назначения ZIP;
  на каждом требуется два текущих объёма данных плюс запас;
- импорт проверяет диск назначения: четыре распакованных объёма архива плюс
  запас для дампа, временных файлов и новой PostgreSQL;
- недоступная оценка свободного места запрещает операцию; при нехватке места
  показываются требуемый и доступный объёмы.

Это консервативные оценки перед операцией в приложении, а не резервирование
места файловой системой. Другой процесс может занять диск позже; восстановление
не публикуется до успешной проверки. Прямой вызов CLI runtime не использует эти
клиентские предварительные проверки.

## Проверки

Автоматические тесты используют временные каталоги: реальные пользовательские
данные не очищаются. Покрыты сохранение текущей копии и трёх новых, возраст,
SHA-256, ссылки, неизвестные пути, устаревший список, незавершённое восстановление,
работающий сервер, отказ до экспорта/импорта и отдельное подтверждение интерфейса
на ширине 390 пикселей. Android не используется.

18 октября 2026 года локально на Windows прошли 78 профильных тестов,
`flutter analyze` без замечаний, проверка COG ≤ 15 без превышений и
`flutter build windows --release`. Установленная пользовательская копия
приложения не запускалась; активного сеанса для hot reload не найдено.
