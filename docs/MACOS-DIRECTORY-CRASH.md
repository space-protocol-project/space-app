# Аварийное восстановление каталога macOS

Стенд от 29 октября 2026 года реализован, но аварийная проверка пока заблокирована:
[GitHub CI 40878160140](https://github.com/space-protocol-project/space-app/actions/runs/40878160140)
успешно выполнил анализ, 127 целевых тестов (один штатный пропуск), COG и нативную сборку, затем получил
`errSecMissingEntitlement` (**−34018**) при первом `PlatformKeyStorage.write`.
До контрольных точек SIGKILL сценарий не дошёл; отчёт проверок пуст.
macOS-критерий milestone остаётся открытым.

Текущие настройки плагина выбирают Data Protection Keychain, а проект использует
ad-hoc подпись (`CODE_SIGN_IDENTITY = "-"`) без настроенной группы доступа Keychain.
Согласно [разъяснению Apple](https://developer.apple.com/forums/thread/114456),
−34018 означает отсутствие необходимого entitlement. Требуется выбрать и
проверить конфигурацию хранения/подписи; ослабление проверки или подмена хранилища
не считаются успешной приёмкой. Производственный `PlatformKeyStorage` этим
срезом не изменён. Стенд использует только синтетические данные.

Работа выполняется в `main`; локальные сборки, тесты и физические устройства
не используются. Workflow — `directory-macos-crash.yml`.

## Системное хранение и изоляция

Решение пользователя после первого CI: поддержать сборки без Apple-подписи
через системное login Keychain. Исправление и повторная аварийная приёмка пока
ожидают итогового CI. Ошибка −34018 выше относится к исходной конфигурации.

### Существующие записи

- Имена ключей и `accountName` не меняются. Существующие записи login Keychain
  читаются на прежнем месте; загрузка не удаляет и не переписывает их.
- Смена backend явная, не реакция на ошибку чтения. Отказ или блокировка Keychain
  передаются вызывающему коду; они не превращаются в пустое хранилище или сброс.
- Записи Data Protection Keychain не удаляются и не переносятся автоматически.
  Такой перенос требует доступа из прежней подписанной сборки: сначала экспорт
  полного устройства в защищённый `.spacedevice`, затем явное восстановление
  в сборке с login Keychain. До экспорта не заменяйте такую установку сборкой
  без её подписи. Один каталог пространств не содержит ключей личности и MLS.
- Отсутствие записи в login Keychain не доказывает её отсутствие в недоступном
  Data Protection Keychain. Проверка CI не объявляет такой перенос выполненным.
- Этот срез не меняет хранение Windows, Linux, Android и iOS. Защита login Keychain
  зависит от состояния системной связки ключей и решения macOS о доступе приложения;
  между разными ad-hoc сборками система может запросить разрешение заново.

CI создаёт отдельное системное Keychain с непустым случайным паролем и временно
выбирает его хранилищем по умолчанию. По завершении возвращаются прежние default
и search list, удаляется только созданное хранилище CI. Проверочный запрос
ограничен этим Keychain; файловой имитации хранилища нет.

По выбору пользователя приложение использует штатный `PlatformKeyStorage` и
`flutter_secure_storage_darwin` с явным `usesDataProtectionKeychain: false`:
настоящее системное login Keychain без синхронизации iCloud. Файловой
замены ключей нет. Источник и получатель получают стабильные отдельные префиксы
ключей и настоящих NSUserDefaults, вычисленные из полного пути одноразового
профиля CI. Префикс сохраняется при холодном запуске и повторной передаче.
Параметры криптографии и сериализация каталога остаются производственными.

Временная сборка стенда добавляет независимое чтение `SecItemCopyMatching`
через нативный канал. Системный запрос явно выбирает созданное CI системное Keychain через
`SecKeychainOpen` и `kSecMatchSearchList`, без Data Protection Keychain; результат сравнивается с журналом, прочитанным
через плагин. В отчёт попадают только backend, признаки проверки и PID,
без ключей и содержимого. Нативный канал подключается только заменой файла
`MainFlutterWindow.swift` внутри одноразового checkout CI; в поставляемом
приложении его нет.

## Матрица и критерии

Используется общая [матрица аварийного восстановления](DIRECTORY-CRASH-RECOVERY.md):
остановка до завершения handshake, после первого кадра, в preview, до/после
записи журнала, после настроек, первого пространства и очистки журнала.
Проверяются оба выбора переноса настроек, новый канал/SAS после отказа,
настоящий срок передачи в 300 секунд и повтор без отката.

Координатор запускает исполняемый файл `.app` напрямую в собственной группе
процессов, сверяет PID контрольной точки и завершает всю свою группу через
SIGKILL. Код возврата обязан подтвердить сигнал. Новый запуск — новый процесс
с тем же пространством имён. После продолжения применения выполняется ещё
один холодный запуск и сверка каталога, настроек, закреплений и прежней личности.
Сохранность и отсутствие новых рабочих ключей проверяются производственным
`KeyIdentityVault`. Новое согласие на применение при запуске не предполагается.

Сервер настоящий, PostgreSQL берётся из закреплённого runtime macOS с проверкой
размера, SHA-256 и CRC. Данные базы, хранилища и профилей не публикуются.
После сценария нативный код удаляет только собственные записи с полным
проверенным префиксом `space-ci-<SHA-256>.` и проверяет отсутствие остатка;
настройки очищаются с тем же ограничением. Остальные записи Keychain и системные
настройки хранилища не изменяются.

Сценарий проверяет аварийное завершение приложения, сохранение системным
хранилищем и холодный запуск. Он не моделирует отключение питания, перезагрузку
macOS, блокировку учётной записи или сбой самого системного процесса Keychain.
Оставшаяся проверка Android выполняется отдельным сценарием в CI.
