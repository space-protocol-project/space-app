# Как читать код Space

Начинать удобно с пользовательского действия: найти его событие, обработчик и результат. Основные операции должны читаться сверху вниз как короткая инструкция. Криптография, SQL, TLS и системные API требуют знания своих правил; эти правила нельзя убрать ради внешней простоты.

## Порядок чтения

| Что нужно понять | С чего начать | Что прочитать затем |
|---|---|---|
| Запуск приложения | client/lib/main.dart | client/lib/app.dart, client/lib/ui/shell.dart |
| Подключение, сообщение, канал | client/lib/src/chat_events.dart | конструктор ChatController и соответствующий частный обработчик |
| Что показывает чат | client/lib/src/chat_state.dart | client/lib/ui/chat_view.dart |
| Запуск и обновление домашнего сервера | client/lib/src/home_events.dart | client/lib/src/home_controller.dart |
| Настройки | client/lib/src/preferences_events.dart | client/lib/src/preferences.dart |
| Запуск сервера | space-server/cmd/space-server/main.go: run | homeEndpoint, configureOwner, newRPCServer, startPublicServer |
| Запрос авторизации | space-server/internal/postgres/auth.go: CreateChallenge | space-server/internal/postgres/challenge.go |
| Безопасная иконка | space-server/internal/postgres/server_icon.go: safeSVG | svgDocument.acceptToken и startElement |

## Правила для новых изменений

- Имя должно объяснять действие или содержимое: event, request, transaction, handler, result. Сокращения допустимы для общеупотребительных типов и небольших локальных циклов.
- Функция отвечает за одну законченную часть задачи. Проверка полей, работа с базой, управление ресурсом и отображение экрана имеют отдельные функции.
- Ошибку или неподходящий случай проверяем в начале и выходим. Основной путь остаётся без глубокой вложенности.
- Несколько вложенных тернарных выражений заменяем понятным выбором с явным приоритетом.
- Объясняем причину необычного ограничения, порядок закрытия или правило безопасности. Комментарий не должен повторять очевидную строку кода.
- Общий помощник вводим для понятного повторяющегося действия. Не заменяем прямую последовательность универсальной системой с неочевидными параметрами.

## Перенос пространства и мобильный клиент

Перенос читается от `HomeExportRequested` / `HomeImportRequested` через
`HomeController` к `HomeTransfer` и CLI `ExportPortable` / `ImportPortable`.
Подготовленный импорт проверяется перед переключением каталога. Постоянный
адрес подписей отделён от сетевого адреса; `verifiedIdentityOrigin` проверяет
подписанную связь с текущим TLS. `platform_capabilities.dart` определяет,
где доступен домашний сервер; проверка применяется и в интерфейсе, и в контроллере.
QR изображения разбираются в отдельном обработчике, камера использует общую форму.

Повторный аудит: 1550 функций приложения и 321 функция сервера в измеренном
собственном рабочем коде, максимум COG 15, превышений нет. Общие Flutter-тесты:
248 успешных, 4 штатных пропуска. Перенос проверен на отдельной PostgreSQL,
включая новый IP, HTTPS, владельца, участника, сообщения и восстановление
прежней карточки владельца после ротации root.
- Таймер, подписка, процесс, слушатель и транзакция имеют явного владельца и место завершения.
- Состояние интерфейса — снимок данных; событие — конкретное действие. Результат команды публикуется до завершения ожидающего Future.
- Сгенерированный код и сторонние библиотеки отделяются от собственного кода. Протокольные проверки не ослабляются ради уменьшения числа условий.

## Небольшой словарь

Событие сообщает, что произошло или что требуется сделать. Состояние описывает, что интерфейс должен показать. Transcript содержит данные запроса, которые подписывает устройство. Grant — сохранённое разрешение устройства. Cursor указывает место в истории сообщений. Fingerprint — отпечаток сертификата или ключа для проверки доверия.

## Что изменено при повторной проверке

Имена служебных операций Bloc стали явными: sendRequest, handleRequest, runAndComplete, publishStateEvent. В обработчиках используется event вместо одиночной буквы. Параметр отправки запроса ограничен семейством событий своего контроллера.

Большой build оболочки разделён на рабочую область, нижнюю навигацию и адаптивную компоновку. Приоритет страниц выбран последовательными проверками вместо вложенных тернарных выражений.

CreateChallenge разделён на проверку полей, подготовку регистрации/существующего разрешения и сохранение запроса. SQL, состав подписываемых данных и одна транзакция сохранены. Запуск сервера разделён на настройку владельца, регистрацию сервисов и запуск публичного HTTPS с явным закрытием слушателя и файла состояния.

Проверка SVG отделяет чтение документа от обработки токена, вложенности и атрибутов. Пределы размера, количества токенов и глубины сохранены.

В Windows исправлен цикл GetMessage: код -1 означает ошибку и не передаётся на обработку как сообщение. Это соответствует [контракту Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagew). Обработчик смены шрифтов проверяет наличие Flutter-контроллера перед обращением к нему.

## Границы проверки

Численно повторно проверены все собственные Dart/Go/Python/JavaScript файлы, тесты и инструменты, доступные анализатору. Основные нативные точки запуска и сценарии упаковки прочитаны отдельно; автоматической метрики для C++, Swift, shell и PowerShell в используемом инструменте нет. Сборки Linux/macOS и их системное поведение локально на Windows не проверялись.

Текущие показатели рабочего кода и отдельный список превышений в тестах и инструментах находятся в COMPLEXITY_AUDIT.md. Читаемость всего проекта не считается окончательно достигнутой только потому, что отдельные оценки снизились.

Причина ошибок AXTree установлена 14 октября 2026 на Flutter 3.47.7: `railButton` создавал подсказку через `IconButton.tooltip`, а его значок содержал ещё один `Tooltip` со статусом сервера. При перемещении указателя между кнопкой сервера и соседними кнопками вложенные подсказки приводили к отправке узлов, недостижимых от корня дерева доступности. Нативный мост Windows сообщал `Failed to update ui::AXTree, error: … will not be in the tree and is not the new root`.

Вложенный `Tooltip` удалён. `serverTooltip` объединяет название, адрес и известный статус соединения в одной подсказке кнопки. Семантика и визуальные подсказки сохранены; SDK Flutter и нативное журналирование не изменялись. В upstream есть [похожий отчёт о Tooltip и AXTree](https://github.com/flutter/flutter/issues/182444), но конкретная причина в Space установлена локальным воспроизведением, а не только совпадением сообщения об ошибке.

Регрессионный тест `client/test/tooltip_semantics_test.dart` проверяет приращения дерева, передаваемые движку, при наведении мыши и смене статуса сервера. До исправления проверка обнаруживала обновления потерянных узлов. После исправления проверяются также полная доступная подпись и состояния «неизвестно», «онлайн», «офлайн». Тесты локализации уведомлений проверяют объединённую подсказку на русском, китайском и английском языках.

Проверка Windows debug: нативное дерево доступности активировано запросом Windows UI Automation; повторены 30 наведений между кнопками сервера и добавления пространства. Ошибок AXTree в нативном журнале нет. Hot reload прошёл, ошибок Dart нет. Это проверка воспроизведённого сценария, а не гарантия отсутствия любых ошибок доступности во Flutter.

Проверка после исправления: `flutter analyze` без замечаний; `flutter test` — 236 успешных тестов, 4 пропущены штатными условиями (два сценария установки/обновления runtime и два сценария создания промоматериалов); `flutter build windows --release` завершён успешно. Новые тесты и изменённые файлы дополнительно проверены анализатором.

Предыдущая проверка рефакторинга: 235 тестов Flutter, анализ без замечаний, Go test/vet, интеграционные тесты с временной PostgreSQL, запуск/остановка demo сервера и Windows Release. Серверные проверки при исправлении AXTree повторно не запускались: изменение касается интерфейса приложения.

## Продолжение упрощения

createOwnSpace теперь только готовит и открывает мастер; чтение настроек, сохранение и переход к управлению выделены в отдельные методы. HomePanel разделяет основную форму, ошибки, управление обновлением, ссылку подключения и кнопку запуска. На сервере prepareHomeRuntime отвечает за подготовку базы и сертификата, validateLocalAddresses — за ограничение локальных слушателей. При ошибке подготовки база закрывается внутри prepareHomeRuntime, после успеха — владельцем run.

Итоговая проверка этого этапа: анализ client без замечаний, 236 тестов Flutter прошли и 4 штатно пропущены; Windows Release собран; Windows debug запущен, hot reload выполнен успешно. go test ./... и go vet ./... прошли. Demo сервер проверен живым запросом healthz (204) и закрытием управляющего stdin (код 0). Полный домашний запуск с PostgreSQL и ручные наведения UI Automation на этом этапе повторно не проверялись.

## Выбор установленного runtime и создание копии

CreateBackup сохраняет последовательность проверок остановки базы; копирование конфигурации и запись манифеста выделены отдельно.

Добавлены проверки чужого каталога установки и неверной контрольной суммы. Анализ Flutter прошёл; все 238 тестов успешны, 4 штатно пропущены. Go test/vet и реальное копирование/восстановление временной PostgreSQL прошли. Windows debug запущен, hot reload успешен. Текущие оценки и оставшиеся функции перечислены в COMPLEXITY_AUDIT.md.

Сборка Windows Release на итоговых исходниках завершена успешно.

Go test/vet прошли с домашним runtime и реальными сценариями временной PostgreSQL. Предыдущий этап зафиксирован коммитами 409cdd4 (приложение) и 534dd32 (сервер). Загрузка обновления отдельно использует проверенный кеш и принимает поток данных с явным закрытием записи. HTTP-обработчик отдельно формирует discovery-документ и обновляет срок записи потокового ответа. Порядок проверок размера, диапазона и контрольной суммы сохранён.

Анализ Flutter без замечаний; 238 тестов прошли, 4 штатно пропущены. Windows Release собран, hot reload успешен. Go test/vet прошли. PostgreSQL на этом этапе повторно не проверялась. Текущий список сложности: 43 функции приложения и 22 сервера с COG > 15. Новые изменения остаются локальными после коммитов 409cdd4 и 534dd32.

Сравнение версий выполняется последовательными проверками; сравнение предварительных идентификаторов выделено в отдельный метод. Фильтр Host/Origin отдельно проверяет допустимый тип содержимого. Порядок отказов и допустимые запросы сохранены.

Анализ Flutter без замечаний; 238 тестов прошли, 4 штатно пропущены; Go test/vet прошли. Windows Release собран. Одновременная сборка Debug/Release привела к неудачному первому debug-запуску с ошибкой AOT; последовательная пересборка Debug исправила запуск, hot reload успешен.
