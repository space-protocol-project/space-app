# Реестр переноса Quiet Space

Дата: 14 октября 2026. База: приложение v0.2.5, 249 тестов прошли, четыре штатно
пропущены; анализ Flutter без замечаний. Незавершённый пользовательский файл
`docs/assets/guides/space-bubble-design.png` не входит в изменения оформления.
Исходные формы сняты из отдельного снимка Git, до изменений темы, в размере
1440×1000. Живой прототип открыт по http://127.0.0.1:8790/; его данные демонстрационные.

«Сохранено» означает, что действие остаётся связано с прежним обработчиком.

кнопки не заменяет проверку операции. Административные формы остаются общими.

## Вложения и новые возможности

В Content API передаётся текст; полноценного транспорта вложений, реакций,
голоса и push нет. Редизайн не добавляет фиктивную отправку файла, реакцию или
медиа-сессию. Системный выбор QR, карточек, значков и архивов сохраняется.
Передача вложений требует отдельного серверного контракта и не блокирует оформление.

## Воспроизведение проверки устройств

Проверка использует тестовый контроллер, 300 искусственных сообщений, хранилище без записи идентичности и эмулированные настройки. Домашний runtime отключён, обновления не выходят в сеть. Снимок камеры не сохраняется; проверяется запуск и получение кадра. Тестовый ввод черновика не заменяет ручную проверку реальной IME.

Из `client`:

```powershell
flutter drive --profile --target integration_test/redesign_device_test.dart --driver test_driver/redesign_device_test.dart -d windows
flutter drive --profile --no-dds --target integration_test/redesign_device_test.dart --driver test_driver/redesign_device_test.dart -d <Android-device-id>
```

На Android нужно разблокировать телефон и разрешить камеру в системном запросе. `--no-dds` нужен для подключения измерителя к VM Service в этой среде. Для отдельного сравнения без эффектов добавить `--dart-define=SPACE_EFFECTS=false`. На Windows проверка физической камеры штатно пропускается. Отчёты и снимки сохраняются в `build/redesign_reports`; перед следующим прогоном сохранить предыдущий отчёт отдельно. Проверки и сборки одного checkout выполнять последовательно: они обновляют общие файлы регистрации плагинов. После них production APK собирается обычной командой `flutter build apk --release`.
- Одна карточка избранного для всей полосы вместо портала на каждом маркере. Проверены повторные наведения, включённая семантика, обновление порядка и удаление активной закладки. Этот тест падает на прежнем коде (теряется следующая карточка) и проходит на изменённом.
- Стеклянная карточка избранного имеет тень с малой непрозрачностью и большим размытием. Заголовок без рамки; выбранные каналы имеют боковые отступы.
- Сведения и поиск используют один компактный стеклянный диалог справа вверху. Убрана анимация прозрачности маршрута, которая давала раздельное появление поверхности и размытия. Golden-панель сведений снята на первом кадре в обеих темах.
- Мобильное меню объединяет реальные пространства, каналы и прежние действия полосы. Ширина до 320, остаётся не меньше 48 логических пикселей страницы. Проверены свайпы, отсутствие перехвата вертикального жеста, Back, возврат фокуса и сохранение черновика при смене ширины. Поиск и подключение открываются после закрытия меню.
- Поле ввода растёт до трети окна; длинный текст прокручивается внутри. При синтетически открытой клавиатуре поле остаётся в доступной области.
- Windows и Android Release собраны. Физические Android-жесты, камера, IME и Windows DPI остаются ручными проверками.
- В прежней Windows Debug-сессии также были сообщения native accessibility_bridge об AXTree. Они отличаются от исходных Flutter layout-исключений; отсутствие этих native-сообщений при всех реальных взаимодействиях пока отдельно не подтверждено.

## Чтение фотографии QR с экрана

На фотографии пользователя (JPEG 3000×4000) прежний распознаватель zxing2
не прочитал код; уменьшение и усиленный поиск результата не дали. Добавлен
локальный резервный распознаватель ZXing-C++ через flutter_zxing 3.1.0.
Он получает уже декодированные пиксели в том же рабочем изоляте. Ограничения
размера файла и изображения, проверка ссылки, приглашения и TLS сохранены.
Фото и содержимое QR в журнал не записываются.

Windows Release собран с новой библиотекой. Семь целевых тестов прошли,
включая чтение исходного пользовательского JPEG в рабочем изоляте, PNG/JPEG,
отказ для неверных ссылок, возобновление камеры и ручное считывание без
одновременного захвата двух кадров. На Honor PCT-L29 проверка галереи в режиме profile также прошла: JPEG
3000×4000 (5 200 311 байт), ссылка появилась в форме, приглашение и
TLS-отпечаток сохранены. Отчёт: build/redesign_reports/android-qr-image.json.
После успешной проверки приложение закрыл тестовый драйвер; журнал содержит
All tests passed, процесс завершился с кодом 0. Подключения к серверу не было.

Исходная фотография не включена в репозиторий. Дополнительный тест
`test/space_qr_photo_test.dart` запускается с
`--dart-define=SPACE_QR_PHOTO=<абсолютный путь к фото тестового QR>`.
Для запуска этого теста на Windows сначала собрать приложение и добавить
`client/build/windows/x64/runner/Release` в PATH текущего процесса, чтобы
тест загрузил собранную flutter_zxing.dll. Без параметра фото тест пропускается.

## Уточнение результатов и оптимизация, 15 октября

После разблокировки телефона и выдачи разрешения повторная проверка камеры
прошла. Последующие измерения прокрутки запускаются с
`--dart-define=SPACE_TEST_CAMERA=false`: пропуск камеры в этих измерениях
намеренный. Windows 125% и 150% исключены из приёмки по просьбе пользователя;
синтетические размеры не считаются проверкой системного DPI.

Подробная трассировка Android показала повторное построение скрытых страниц
при прокрутке чата. `RetainedIndexedStack` сохраняет экземпляр скрытой страницы
и обновляет его при возвращении. На переходе в скрытое состояние передаётся
последнее обновление, чтобы чат перестал отмечать сообщения прочитанными.
Подписки и состояние страниц сохраняются; изменения темы и других inherited
зависимостей по-прежнему доставляются Flutter.

В одинаковом сценарии трассировки число построений SettingsPanel, Dashboard
и OverviewPanel уменьшилось с трёх для каждого до нуля. Наибольшая длительность
BUILD в подробной трассировке уменьшилась с 47,2 до 15,6 мс. Это отдельная
диагностика с инструментированием, а не обещание постоянной частоты кадров.
Обычные замеры на Honor PCT-L29 остаются переменными: последний прогон дал
среднее построение 6,25 мс и растеризацию 13,02 мс; 19 и 17 кадров соответственно
превысили бюджет 16,7 мс. Все измерения выполняются в profile, с включённым стеклом.
Для подробного следа добавить `--dart-define=SPACE_PROFILE_WIDGETS=true`;
трассировка снимается отдельно после основного измерения.

Дополнительно обычный текст не проходит через Markdown-парсер, неизменённые
списки сообщений и каналов повторно используются в неизменяемом снимке состояния,
а отметки прочтения записываются в историю одной отложенной операцией. При закрытии
контроллера последняя запись ожидается. Выделение, копирование и Markdown сохранены.
Проверки неизменяемости снимков, последней записи при закрытии, сохранности черновика
и отсутствия перестроений скрытой страницы добавлены в автоматические тесты.

Из мобильной переписки убран дублирующий выбор канала под стеклянным заголовком.
Все каналы, включая архивные, и обновление каталога доступны в меню.
`mobile_channel_layout_test` проверяет верхний отступ истории и доступность архива.
