# Реестр переноса Quiet Space

Дата: 14 октября 2026. База: приложение v0.2.5, 249 тестов прошли, четыре штатно
пропущены; анализ Flutter без замечаний. Незавершённый пользовательский файл
`docs/assets/guides/space-bubble-design.png` не входит в изменения оформления.
Исходные формы сняты из отдельного снимка Git, до изменений темы, в размере
1440×1000. Живой прототип открыт по http://127.0.0.1:8790/; его данные демонстрационные.

## Вложения и новые возможности

В Content API передаётся текст; полноценного транспорта вложений, реакций,
голоса и push нет. Редизайн не добавляет фиктивную отправку файла, реакцию или
медиа-сессию. Системный выбор QR, карточек, значков и архивов сохраняется.
Передача вложений требует отдельного серверного контракта и не блокирует оформление.

## Уточнения интерфейса и регрессии

- Обзор состоит из карточек пространств с реальными каналами и значками; все прежние операции подключения, импорта, создания, переключения и удаления сохранены. ServerInbox использует ленивый список, поиск и фильтры; неизвестная доступность отделена от офлайн. Проверены 32 пространства, удвоенный текст, пустой поиск и действия строки на RU/EN/中文.
- Общий пакет `space_admin_ui` оформляется темой потребителя. `SpaceContentInsets` находится в общем пакете и не зависит от каркаса приложения; поля и список управления учитывают фактическую высоту заголовка. Поиск `pubspec.yaml` в трёх рабочих репозиториях подтвердил одного текущего потребителя — `client`; отдельный анализ пакета прошёл без замечаний. Проверки каналов, прав, конфликтов, приглашений, устройств и восстановления проходят в полном наборе клиента.
- Контраст основного, вторичного и выделенного текста проверен для тёмного/светлого Gruvbox, Ocean и Iris; пары текста и поверхности имеют отношение не менее 4.5:1. Общая тема оформляет Card, Dialog и PopupMenu, независимые прокрутки не используют общий primary controller.
- Настоящий Windows target, profile: переход в чат, сохранение черновика при поиске, 300 сообщений, шесть плавных прокруток по 400 пикселей, десять переключений карточки избранного с включённой семантикой. Прогон успешен; native AXTree-сообщений в этом прогоне не было. Это ограниченная проверка, а не утверждение об отсутствии ошибок при всех взаимодействиях.
- Windows profile после исправления Escape, 163 измеренных кадра: среднее построение 1.670 мс, максимум 10.804 мс; средняя растеризация 2.488 мс, максимум 4.723 мс; превышений бюджета по этим двум показателям нет. Отчёт и снимок: `client/build/redesign_reports/windows.json`, `windows-search.png`. Они не содержат пользовательской истории и не включаются в Git.

## Воспроизведение проверки устройств

Проверка использует тестовый контроллер, 300 искусственных сообщений, хранилище без записи идентичности и эмулированные настройки. Домашний runtime отключён, обновления не выходят в сеть. Снимок камеры не сохраняется; проверяется запуск и получение кадра. Тестовый ввод черновика не заменяет ручную проверку реальной IME.

Из `client`:

```powershell
flutter drive --profile --target integration_test/redesign_device_test.dart --driver test_driver/redesign_device_test.dart -d windows
flutter drive --profile --target integration_test/redesign_device_test.dart --driver test_driver/redesign_device_test.dart -d <Android-device-id>
```

На Android нужно разблокировать телефон и разрешить камеру в системном запросе. На Windows проверка физической камеры штатно пропускается. Отчёты и снимки сохраняются в `build/redesign_reports`. Проверки и сборки одного checkout выполнять последовательно: они обновляют общие файлы регистрации плагинов. После них production APK собирается обычной командой `flutter build apk --release`.
- Одна карточка избранного для всей полосы вместо портала на каждом маркере. Проверены повторные наведения, включённая семантика, обновление порядка и удаление активной закладки. Этот тест падает на прежнем коде (теряется следующая карточка) и проходит на изменённом.
- Стеклянная карточка избранного имеет тень с малой непрозрачностью и большим размытием. Заголовок без рамки; выбранные каналы имеют боковые отступы.
- Сведения и поиск используют один компактный стеклянный диалог справа вверху. Убрана анимация прозрачности маршрута, которая давала раздельное появление поверхности и размытия. Golden-панель сведений снята на первом кадре в обеих темах.
- Мобильное меню объединяет реальные пространства, каналы и прежние действия полосы. Ширина до 320, остаётся не меньше 48 логических пикселей страницы. Проверены свайпы, отсутствие перехвата вертикального жеста, Back, возврат фокуса и сохранение черновика при смене ширины. Поиск и подключение открываются после закрытия меню.
- Поле ввода растёт до трети окна; длинный текст прокручивается внутри. При синтетически открытой клавиатуре поле остаётся в доступной области.
- Windows и Android Release собраны. Физические Android-жесты, камера, IME и Windows DPI остаются ручными проверками.
- В прежней Windows Debug-сессии также были сообщения native accessibility_bridge об AXTree. Они отличаются от исходных Flutter layout-исключений; отсутствие этих native-сообщений при всех реальных взаимодействиях пока отдельно не подтверждено.
