# Первый срез форума

Статус: локальная реализация 22 октября 2026 года, ещё не выпущена. Опубликованная пара клиент v0.7.12 / runtime v0.7.9 содержит голосовые комнаты на 2–32 участника, но не форум. Для форума нужны новый клиент и runtime со схемой 27, capability `core.forum.v1` и `core.forum.attachments.v1` для файлов.

## Сценарий

1. Подключитесь к пространству и откройте «Форум». Владелец или администратор открывает «Разделы и права», создаёт раздел и настраивает ACL. Тип раздела неизменяемый; обычные чаты остаются отдельными.
2. Участник с правами чтения и записи создаёт тему с заголовком и первым сообщением. Другие участники отвечают в ней. Читатель видит обсуждение без действий записи.
3. Владелец, администратор или назначенный через ACL модератор с эффективными правами `read` и `manage` закрывает тему с подтверждением. Устройство должно иметь scope `space.manage`; ACL не расширяет разрешения устройства. Роль автора не разрешает закрытие сама по себе.
4. Закрытая тема остаётся доступной для чтения. Сервер запрещает новые ответы всем, включая владельца и автора, даже при прямом RPC. Повтор уже принятого ответа с прежним ключом возвращает тот же ответ и не создаёт новый.

Назначение модератора: в панели прав выберите участника и включите видимость, чтение и управление. Глобальная роль `moderator` не вводится. Если устройству ранее не разрешён административный доступ, соответствующий scope необходимо выдать через существующий root-подписанный процесс разрешения устройства; галочка ACL сама его не выдаёт. В первом срезе отдельного диалога получения этого scope для обычного участника нет. Владелец/администратор пользуется существующим подтверждением административного доступа в настройках.

## Контракт и хранение

[forum.proto](../../space-protocol/protocol/proto/space/v1/forum.proto) описывает `ForumService`: список тем, тема со страницей ответов, создание, ответ, закрытие. Доступны gRPC и HTTP Connect; отдельные REST-маршруты для форумного контента в этом срезе не вводятся. Управление разделами использует существующий ChannelService и его REST-маршруты.

`forum_threads` и `forum_replies` отделены от сообщений чата. Раздел имеет тип `forum`, не поддерживает MLS и публичное превью. Текст хранится на сервере без сквозного шифрования; интерфейс явно сообщает об этом. Реакции, редактирование, повторное открытие, закрепления, непрочитанное, уведомления, поиск, экспорт, лента и personas остаются последующими срезами. Обновление списка и обсуждения — явной кнопкой, без имитации обновлений в реальном времени.

Заголовок ограничен 320 байтами UTF-8, сообщение — 8192, ключ идемпотентности — 128. Поле ввода общее с чатом и имеет такой же пользовательский предел 1024 символа; сервер независимо проверяет размер UTF-8. До пяти вложений по 20 МиБ; пустой текст разрешён только при наличии вложения. Страницы содержат до 50 записей; курсор — sequence последней записи, 0 в ответе означает конец. Темы упорядочены по созданию, ответы — по последовательности внутри темы. Счётчик тем ограничен разделом, ответов — темой.

Ключи идемпотентности создания/ответа ограничены разделом и автором и проверяют исходное содержимое запроса. Автор берётся из сессии. Запрос с тем же ключом и другим содержимым получает AlreadyExists. Закрытие передаёт ожидаемую ревизию: конкурентный ответ меняет её и вызывает Aborted, после которого надо обновить тему. Закрытие записывается в `admin_audit` вместе с исполнителем и идентификатором темы.

При каждом RPC сервер заново проверяет сессию, членство, блокировку, разрешения устройства, настройки пространства и ACL. Порядок блокировок: разрешение устройства → членство → настройки → канал. Мутации сериализованы блокировкой канала, чтение удерживает FOR SHARE до получения согласованной страницы. Это простой первый срез; параллельные записи в разные темы одного раздела пока сериализуются. Архивирование запрещает мутации, удаление раздела каскадно удаляет темы и ответы. API чата не принимает форумный контент.

## Проверки и дальнейшая приёмка

Серверные интеграционные тесты `internal/postgres/forum_test.go` используют настоящую PostgreSQL и сетевой gRPC/Connect: ACL автора и модератора, отзыв права, запрет ответов после закрытия, конфликт ревизий, гонка ответа и закрытия, повтор ключей, страницы, изоляция разделов, перезапуск хранилища и каскадное удаление. Тесты транспорта проверяют авторизацию до декодирования тела для каждого форумного RPC.

Flutter `test/forum_test.dart` проверяет старый runtime, страницы, обновление обсуждения, очистку после отзыва доступа, завершение запроса после dispose, сохранение черновика/ключа при ошибке, создание/ответ/закрытие в интерфейсе и режим читателя.

Ручная приёмка после сборки нового runtime: два настоящих клиента и отдельный модератор, создание раздела, выдача и отзыв прав, тема и ответ с разных устройств, закрытие, попытка ответа со старой открытой страницы, архивирование и перезапуск сервера. Проверить узкий экран, длинный русский/китайский текст и нестабильную сеть. Модельный widget-тест не заменяет эту приёмку.

Предыдущая проверка текстового среза 22 октября 2026: `go test ./... -count=1` с настоящей PostgreSQL прошёл; 6 форумных интеграционных тестов прошли отдельно, включая миграцию 25 → 26 без изменения прежних данных, server ID и лимита голосовой комнаты 32. Полный Flutter-прогон — 776 passed, 17 skipped. `flutter analyze` клиента и space_admin_ui — без замечаний, `python tools/check_complexity.py` — максимум COG 15, превышений нет. Windows Debug собран, запущен и проверен hot reload; `buf lint` и проверки пробельных ошибок diff прошли. Новая пара версий и CI для этого среза ещё не публиковались.

## Плотный интерфейс и поле чата

Обновление 22 октября 2026: список тем без отдельных больших карточек, метаданные и счётчик ответов в строке; первое сообщение выделено, ответы разделены тонкими линиями. В широком окне справа показана информация о разделе/теме, в узком — одна колонка и меню действий. Закрытие перенесено в меню модератора с подтверждением; закрытая тема показывает информационную плашку без формы отправки. Длинное название раздела на узком экране получает отдельную строку. Палитра, шрифты и поверхность поля ввода используют тему Space.

Чат и форум используют общие `MessageDraftField`, `MessageComposerActions`, `MessageInputSurface` и обработчик Enter/Shift+Enter. В них совпадают отступы, границы, подсказка, выбор эмодзи, добавление файлов и круглая кнопка отправки. Предпочтение сочетания клавиш передаётся из настроек приложения. При ошибке сохраняются текст, очередь файлов и ключ запроса; повтор не создаёт вторую публикацию. Отправка без текста с файлом работает.

Миграция 27 добавляет JSON-метаданные вложений к темам/ответам и внешние ключи `assets.forum_thread_id` / `assets.forum_reply_id`. Привязка файлов и публикация выполняются одной транзакцией под блокировкой раздела. Используется общий сервис файлов: автор и канал загрузки, готовность, отсутствие другой привязки, лимит пяти файлов, квоты, запрет администратора и ACL проверяются сервером. Чужой файл, повторная привязка и новый ответ в закрытую тему отклоняются. Опубликованный файл нельзя отменить как незавершённую загрузку. Скачивание заново проверяет ACL; удаление раздела удаляет файлы, а очистка незавершённых загрузок их сохраняет. Файлы форума доступны и в общем каталоге файлов раздела.

Кнопка вложений показывается только при разрешённой политике файлов и capability `core.forum.attachments.v1`. Это защищает от отправки нового поля старому runtime, который мог бы его проигнорировать. Вложения в начальном текстовом срезе схемы 26 отсутствуют.

[Новые снимки настоящих Flutter-виджетов](screenshots/forum/README.md) показывают три состояния на широком и узком экранах. Данные демонстрационные; снимки не подтверждают ручную приёмку нескольких физических клиентов.

Проверка после реализации дизайна и файлов: полный Flutter-прогон 777 passed / 19 skipped; анализ клиента чистый, COG ≤15 без превышений. Windows Debug собран, запущен, hot reload прошёл. Семь форумных интеграционных тестов на PostgreSQL прошли, полный пакет postgres прошёл за 173 с; остальные Go-пакеты прошли с повтором home после ошибки очистки временного каталога Windows. `buf lint` и `git diff --check` прошли.
