# Постоянная очередь обычных сообщений — v0.4

Основание: ADR-037 в репозитории протокола. Контракт и схема сервера не меняются; подходит runtime v0.3.6.

## Поведение

Кнопка отправки сначала сохраняет текст, ID канала, ссылки на уже загруженные вложения и случайный ключ запроса в защищённом хранилище ОС. Только после успешной записи поле ввода очищается. Подтверждение сохранения в очереди отличается от подтверждения сервера.

Очередь читается при подключении прежнего устройства и при восстановлении проверенной локальной истории. В известный доступный для записи канал можно добавить текст без сети. Если приложение запущено без сети и локальная история ещё никогда не сохранялась, сначала понадобится подключение, чтобы получить права каналов.

После обрыва выполняется повтор того же запроса с прежним ключом: задержки 1, 2, 4, 8, 16 и 32 секунды, далее не чаще раза в 32 секунды. Повторяется только временная ошибка соединения, тайм-аут или отменённый транспортный запрос. Приложение должно работать; при следующем запуске очередь возобновляется после подключения. Закрытое приложение не выполняет фоновую отправку.

Сервер уже хранит ключ идемпотентности вместе с сообщением в PostgreSQL. Если сервер сохранил сообщение, но ответ потерялся, повтор возвращает прежний ID. Два отдельных нажатия отправки с одинаковым текстом создают два разных сообщения: дедупликация определяется ключом запроса, а не текстом.

Отправка использует сохранённый ID канала, независимо от открытого экрана. Порядок сохраняется внутри канала. Остановленное сообщение блокирует последующие сообщения этого канала, но не очередь другого канала. На узком экране, в невысоком окне или при увеличенном тексте очередь открывается компактной кнопкой со счётчиком в прокручиваемом диалоге. На широком экране список находится над полем ввода. Ошибки прав, содержимого и неподходящие подтверждения останавливают запись в очереди; пользователь может повторить действие или убрать его с предупреждением. Удаление из очереди не удаляет уже принятое сообщение на сервере.

## Сохранность и границы

- Область хранения связана с постоянным origin, server ID, principal ID и grant ID. Смена адреса подключения не меняет эту область. Очередь не переносится автоматически на другое разрешение/устройство; при смене grant отправка прежней очереди останавливается. Восстановление её на новом grant — отдельная задача.
- Данные не записываются открытым текстом в SharedPreferences. Изменения выполняются через защищённое хранилище и блокировку файла в каталоге приложения; содержимое файла блокировки не содержит сообщений. Чтение и изменение одной области сериализованы, в том числе для разных экземпляров хранилища.
- Не более 100 записей и 1 МиБ сериализованных данных. Заполненная очередь продолжает отправлять прежние сообщения. Записи не вытесняются, не обрезаются и не удаляются по сроку хранения истории.
- Ошибки чтения или записи не превращаются в пустую очередь. При неподтверждённой записи текст остаётся в поле ввода. Повреждённое значение сохраняется, автоматическая отправка блокируется.
- Перед удалением запроса проверяются канал, автор, ID, последовательность и версия ответа; для первой версии также текст и ID вложений. История сохраняется до удаления запроса. Сбой записи истории или удаления оставляет тот же ключ для безопасного повтора. Поздние результаты прежнего подключения не меняют очередь другого пространства.
- Отказ доступа скрывает локальные данные и прекращает отправку, но не стирает несданные сообщения из защищённой очереди. Явная команда очистки локальных данных удаляет и очередь соответствующей области.
- Сохраняются ссылки на **уже загруженные** вложения. Сам выбор локальных файлов, незавершённая загрузка и копирование их содержимого на диск очереди в этот этап не входят. Незакреплённые файлы сервер может очищать через 24 часа; такая отправка остаётся остановленной в очереди и требует повторного прикрепления файла. Текст запроса не теряется.
- Эта очередь относится к созданию сообщений обычного канала. MLS продолжает использовать собственную зашифрованную очередь. Правки, удаления и обычные реакции пока выполняются онлайн.

## Проверки

`client/test/chat_outbox_test.dart`: запись до сети, восстановление порядка, потеря ответа, автоматический повтор, разные сообщения с одинаковым текстом, смена канала/пространства, ошибки истории/диска/прав, повреждённое хранилище, лимиты, изоляция областей, смена grant и отзыв доступа.

`client/test/live/attachments_server_test.dart`: настоящий ConnectRPC и PostgreSQL; сообщение с файлом фиксируется на сервере, прокси теряет ответ, новый контроллер читает прежнюю очередь, повторяет прежний ключ, второй клиент видит ровно одно сообщение и скачивает исходные байты.

`client/tool/native_vault_drill.dart` и `.ps1`: настоящая Windows Release-сборка; запись очереди и чтение в другом процессе вместе с ключами и избранным. Проверяется прежний сценарий прерванной записи и очистка отдельного случайного тестового слота. Пользовательские пространства не используются.

Визуальные эталоны прежнего интерфейса проходят без обновления. Ручная приёмка физического Android остаётся открытой.

Итог локальной приёмки 16 октября: 421 Flutter-тест прошёл, восемь штатно пропущены; анализатор без замечаний. На 390 px и масштабе текста 150% проверены три языка, список и подтверждение удаления. Прежние Windows-эталоны не изменялись. Настоящие RPC/БД и нативное хранилище проверены описанными сценариями. Когнитивная сложность: 140 файлов, 1411 функций, максимум 15, превышений нет; девять тестов профиля проходят.

Обычная Windows Release-сборка `client/lib/main.dart` также прошла. Выпущено в [v0.4.0](https://github.com/space-protocol-project/space-app/releases/tag/v0.4.0). [Релизный CI](https://github.com/space-protocol-project/space-app/actions/runs/38886832405) прошёл: четыре установщика, MLS, настоящие RPC/БД и нативное хранилище Windows. SHA-256 четырёх файлов сверены с GitHub. Совместимый runtime — v0.3.6. Физический Android и полная приёмка нескольких устройств остаются открытыми.


## Продолжение v0.4: два устройства и длительный обрыв

16 октября проверен новый срез, ещё не выпущенный. Физический Android не использовался.

- `test/live/ordinary_sync.dart` включён в существующий `attachments_server_test.dart`, поэтому выполняется и в серверном CI, когда выбран новый коммит приложения. Настоящее сопряжение создаёт два разных grant одной личности, а не копирует ключ устройства. Клиенты имеют независимые очереди, хранилища истории и RPC-соединения.
- Одновременная отправка пяти пар одинаковых текстов создаёт десять разных сообщений. Оба клиента сходятся по ID, sequence, тексту и revision, ключи двух очередей не пересекаются.
- Первый клиент теряет подтверждение после фиксации сообщения сервером, отключается и сохраняет ещё два сообщения. Второй правит принятое сообщение и отправляет новое, затем ещё 105 сообщений — больше страницы истории. Первый перезапускается при всё ещё отключённой сети, читает прежние ключи и автоматически подключается после восстановления. Повтор возвращает актуальную правку, старый текст не восстанавливается, дубля нет. Проверяется также сохранение записей с датой создания 45 дней назад; это искусственно состаренная очередь, не реальное ожидание 45 суток.
- Отдельный тест с `fake_async` проводит двое суток без сети с настоящим расписанием повторов 1–32 секунды: более 5000 попыток не блокируют и не удаляют очередь. После пересоздания контроллера уходят ровно три запроса с прежними ключами. Здесь время ускорено, транспорт и хранилище — тестовые; настоящее RPC/БД и файловые блокировки проверены предыдущим сценарием.
- Исправлены остановка очереди при истечении сессии, отсутствие повторного подключения после запуска без сети и ошибочная блокировка при оборванном HTTP-ответе. Повторный вход ограничен одной попыткой на доставку; прежний grant и область проверяются снова. Повторный отказ, смена grant, отзыв, ошибки хранения и явное отключение покрыты проверками. Явное отключение отменяет таймер и не возобновляет отправку самостоятельно. Итоговая история двух клиентов содержит 121 сообщение с одинаковыми ID, порядком, текстом и версиями.

Приёмка: 427 тестов Flutter прошли, восемь штатно пропущены; анализ без замечаний. Новая сквозная проверка ConnectRPC/PostgreSQL прошла с обычным и потерянным ответом, правкой со второго устройства и явным отключением. Когнитивная сложность — 140 файлов, 1413 функций, максимум 15, превышений нет. Девять тестов профиля сложности, hot reload без ошибок времени выполнения и обычная Windows Release-сборка `lib/main.dart` прошли. Приложение в закрытом состоянии не выполняет фоновые отправки; перенос очереди между устройствами и незавершённые загрузки остаются отдельными задачами.


Продолжение: [постоянная очередь локальных файлов](QUEUED-FILES.md). Выбранные вложения теперь сохраняются при нажатии «Отправить» и восстанавливают загрузку без исходника; черновики до отправки, перенос на новый grant и очередь правок/удалений/реакций остаются отдельными задачами.
