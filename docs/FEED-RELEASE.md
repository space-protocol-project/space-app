# Подготовка совместимого выпуска ленты

24 октября 2026. Подготовлены версии клиента **v0.7.19+49** и runtime **v0.7.15**. Миграция PostgreSQL **30→31**, голосовой профиль **3**, capability **core.feed.v1**. Новая пара ещё не опубликована; текущая публичная пара — v0.7.18 / v0.7.14.

## Проверяемая пара

- Исходники протокола, клиента и сервера сохраняются в отдельных ветках подготовки. Посторонние изменения не включаются.
- `.github/space-server.ref` приложения закрепляет точный SHA сервера для сквозной проверки.
- `.github/space-app.ref` сервера закрепляет клиент с реализацией ленты; ручные проверки также получают точный app_ref кандидата.
- Linux CI выполняет настоящие RPC с отдельной PostgreSQL: раздельные права, публикация участником с файлом, повтор без дубля, комментарий, отдельный модератор, скрытые данные и запрет следующего фрагмента файла, восстановление и SHA-256 полного скачивания.
- Ручной запуск home-runtime.yml с `version=v0.7.15` собирает кандидат для Windows x64, Linux x64 и macOS arm64 и выполняет проверки совместимого клиента. Этот запуск не публикует GitHub Release. Версию кандидата нельзя подставить вместо релизного тега.

Android входит в выпуск. Проверены мобильные widget-сценарии, Java-тесты и отладочные APK трёх архитектур. Штатный релизный CI должен собрать APK с ключом выпуска. Проверка на физическом Android отложена по решению пользователя; она не блокирует текущий выпуск. Приёмка физической сети, гарнитур и голоса сохраняет прежние ограничения.

## Порядок публикации

1. Завершить CI подготовленных исходников, проверить архивы кандидата и сохранить ссылки на результаты.
2. Включить согласованные изменения в основные ветки репозиториев. Проверить changelog, версию 0.7.19+49 и точные перекрёстные ссылки.
3. Поставить тег runtime v0.7.15. Дождаться полного релизного CI и публикации трёх архивов, трёх JSON-дескрипторов и SHA256SUMS.txt.
4. Полностью скачать опубликованные файлы и проверить их размеры/SHA-256. Пройти штатную проверку установки опубликованного runtime.
5. Выполнить `python packaging/pin-home-runtime.py v0.7.15` в space-app, проверить каталог и целевые тесты обновления. До этого момента каталог сохраняет проверенный опубликованный v0.7.14: ссылки на ещё не опубликованные файлы в приложение не записываются.
6. Закоммитить каталог, поставить тег клиента v0.7.19, дождаться релизных проверок Windows/macOS/Linux и подписанного Android APK.
7. Проверить четыре опубликованных установщика и SHA256SUMS.txt; обновить сведения о реально опубликованной паре в README, руководствах и TODO.

Подготовка веток и сборка кандидата отделены от публикации. Релизные теги запускают публичный выпуск автоматически.

## Обновление установленного пространства

Перед миграцией сохранить резервную копию пространства и ключей MLS. Установить новый клиент, затем применить runtime v0.7.15 в «Эфире». Установленные данные остаются отдельно от архива runtime. Старый клиент не поддерживает разделы feed. Возврат к runtime схемы 30 после миграции 31 без восстановления резервной копии не заявляется.
