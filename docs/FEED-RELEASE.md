# Подготовка совместимого выпуска ленты

24 октября 2026. Подготовлены версии клиента **v0.7.19+49** и runtime **v0.7.15**. Миграция PostgreSQL **30→31**, голосовой профиль **3**, capability **core.feed.v1**. Новая пара ещё не опубликована; текущая публичная пара — v0.7.18 / v0.7.14.

## Проверяемая пара

Инструменты на 24 октября: стабильные Flutter 3.47.8 / Dart 3.13.7, Go 1.27.3 и Rust 1.99.1. Rust синхронизирован между CI и native hooks.

Для устранения RUSTSEC-2026-0387 заменён прежний криптографический провайдер: OpenMLS 0.9.2, libcrux с обновлёнными стабильными примитивами, ed25519-dalek 3.0.0; независимая проверка mls-rs использует AWS-LC. Сохранения и сообщения старой реализации проверяются отдельным тестом миграции.

Клиент переведён на cross_file 0.4.0, desktop_drop 0.9.2 и screen_retriever 0.3.0. Пока опубликованные плагины камеры и выбора файлов используют старые вызовы cross_file, их стабильные исходники адаптированы в `client/vendor`; каждый изменённый пакет сохраняет лицензию и `SPACE-PATCH.md`. Временные источники перетаскивания читаются с ограничением размера до завершения обработчика, ошибки остаются в AttachmentQueue.

Данные файлов и чтение локального диска остаются независимыми от Flutter (`files.dart`); `cross_file` и системные диалоги подключаются только адаптером интерфейса (`file_picker.dart`). CI отдельно компилирует обычным Dart служебные программы запуска и переноса runtime, чтобы обновление файловых плагинов не добавило туда зависимость от `dart:ui`.

Ограничения косвенных Dart-зависимостей: material_color_utilities 0.13.0 и test_api 0.7.12 закреплены самим последним стабильным Flutter; http2 2.3.1 ограничен последними grpc 5.2.0 и connectrpc 2.0.1; xml 7.0.1 ограничен верхней границей последнего vector_graphics_compiler 1.3.2. Они не заменяются несовместимыми версиями через overrides. Повторная проверка нужна при выходе обновлений соответствующих родительских пакетов.

- Исходники протокола, клиента и сервера сохраняются в отдельных ветках подготовки. Посторонние изменения не включаются.
- `.github/space-server.ref` приложения закрепляет точный SHA сервера для сквозной проверки.
- `.github/space-app.ref` сервера закрепляет клиент с реализацией ленты; ручные проверки также получают точный app_ref кандидата.
- Linux CI выполняет настоящие RPC с отдельной PostgreSQL: раздельные права, публикация участником с файлом, повтор без дубля, комментарий, отдельный модератор, скрытые данные и запрет следующего фрагмента файла, восстановление и SHA-256 полного скачивания.
- Ручной запуск home-runtime.yml с `version=v0.7.15` собирает кандидат для Windows x64, Linux x64 и macOS arm64 и выполняет проверки совместимого клиента. Этот запуск не публикует GitHub Release. Версию кандидата нельзя подставить вместо релизного тега.

Android входит в выпуск. Проверены мобильные widget-сценарии, Java-тесты и отладочные APK трёх архитектур. Штатный релизный CI должен собрать APK с ключом выпуска. Проверка на физическом Android отложена по решению пользователя; она не блокирует текущий выпуск. Приёмка физической сети, гарнитур и голоса сохраняет прежние ограничения.

## Порядок публикации

Перед публикацией новая пара повторно проходит CI после доработки завершения:

- Сервер при SIGINT/SIGTERM или EOF в `-managed` перестаёт принимать запросы на локальном HTTP и публичном HTTPS одновременно. Подписки отменяются; принятые обычные запросы завершаются при доступном внутреннем gRPC в пределах общего срока 10 секунд. По истечении срока соединения принудительно закрываются, результат содержит ошибку.
- На завершение каждого из трёх ресурсов (планировщик копий, публичные сетевые ресурсы, пул PostgreSQL) отведено до 5 секунд. Собственная PostgreSQL останавливается через `pg_ctl -m fast`, ожидание команды ограничено 20 секундами. Системная и отдельно размещённая база не останавливаются.
- Приложение объединяет запросы окна и ОС, блокирует новые действия во время выхода, ждёт текущие операции до 10 секунд, запись настроек/черновиков до 5 секунд, голос до 5 секунд и отключение клиентов до 12 секунд. Для собственного серверного процесса закрывает stdin (до 3 секунд), ждёт выхода до 55 секунд и проверяет отсутствие `postmaster.pid`. Общий срок выхода — 100 секунд. Ненулевой код, незавершённая операция, неподтверждённое сообщение или таймаут оставляют окно открытым с сообщением; чужие процессы не завершаются.
- Автоматические проверки охватывают оба HTTP-входа, сохранение принятых RPC, отмену подписок, принудительную остановку при таймауте, обработчик без реакции на отмену, ограничение фоновой очистки и завершение настоящего Go-процесса по EOF. Dart проверяет EOF/код/таймаут настоящего дочернего процесса, объединение запросов и ожидание очистки окна на трёх настольных платформах.

Принудительное убийство процесса, отключение питания и работа аппаратного Android в эти проверки не входят.

1. Завершить CI подготовленных исходников, проверить архивы кандидата и сохранить ссылки на результаты.
2. Включить согласованные изменения в основные ветки репозиториев. Проверить changelog, версию 0.7.19+49 и точные перекрёстные ссылки.
3. Поставить тег runtime v0.7.15. Дождаться полного релизного CI и публикации трёх архивов, трёх JSON-дескрипторов и SHA256SUMS.txt.
4. Полностью скачать опубликованные файлы и проверить их размеры/SHA-256. Пройти штатную проверку установки опубликованного runtime.
5. Выполнить `python packaging/pin-home-runtime.py v0.7.15` в space-app, проверить каталог и целевые тесты обновления. До этого момента каталог сохраняет проверенный опубликованный v0.7.14: ссылки на ещё не опубликованные файлы в приложение не записываются.
6. Закоммитить каталог, поставить тег клиента v0.7.19, дождаться релизных проверок Windows/macOS/Linux и подписанного Android APK.
7. Проверить четыре опубликованных установщика и SHA256SUMS.txt; обновить сведения о реально опубликованной паре в README, руководствах и TODO.

Подготовка веток и сборка кандидата отделены от публикации. Релизные теги запускают публичный выпуск автоматически.

## Обновление установленного пространства

Перед миграцией сохранить резервную копию пространства и ключей MLS. Установить новый клиент, затем применить runtime v0.7.15 в «Эфире». Установленные данные остаются отдельно от архива runtime. Старый клиент не поддерживает разделы feed. Возврат к runtime схемы 30 после миграции 31 без восстановления резервной копии не заявляется.
