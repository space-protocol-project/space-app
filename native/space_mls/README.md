# Экспериментальное ядро MLS Space

OpenMLS 0.9.2, RFC 9420, провайдер libcrux и набор `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`. До 256 устройств в группе; каждое устройство имеет отдельный MLS signing key с подписью существующего Space device key. Доверие не выводится из имени участника или одного ответа сервера.

Зависимости адаптированного провайдера закреплены в `../vendor/openmls_libcrux_crypto`; происхождение, лицензия и изменения описаны в `SPACE-PATCH.md`. Подписи устройств выполняет ed25519-dalek 3.0.0. Формат сохранений прежнего провайдера сохраняется: `tests/provider_migration.rs` восстанавливает настоящий зашифрованный снимок OpenMLS 0.9.1 и проверяет старые сообщения.

Реализованы KeyPackage, Welcome, Add/Remove/Commit, сообщения и отдельное XChaCha20-Poly1305 шифрование вложений. Получатель проверяет отправителя и ожидаемый состав группы; ошибочный пакет обрабатывается в отдельном состоянии и не расходует ключ подлинного сообщения. Новые устройства не получают старую историю автоматически.

Состояние OpenMLS и исходящая очередь сохраняются зашифрованными. Flutter хранит снимок, revision, доверенные коды, сообщения и точную очередь доставки одной записью защищённого хранилища ОС с последовательным доступом и межпроцессной блокировкой. Это не аппаратная защита от полного отката ОС-хранилища.

Мост `native/space_mls_bridge` предоставляет небольшой JSON/C ABI. Пакет `packages/space_mls_native` собирает и включает библиотеку через Dart native hooks. `unsafe` запрещён в ядре; мост ограничивает его границей FFI. При обновлении OpenMLS требуется совместимая миграция снимков.

## Проверки

Из этого каталога с Rust 1.99.1:

```text
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

23 теста проверяют четыре устройства, смену состава, подпись привязки, повтор пакетов, подмену контекста, файлы и перезапуск, включая незавершённый Commit и KeyPackage до Welcome. Clippy запрещает когнитивную сложность выше 15.

Полный отчёт: [MLS-CHECKS.md](../../docs/MLS-CHECKS.md). Это экспериментальная интеграция без внешнего криптографического аудита и проверки совместимости с независимой библиотекой. Существующая recovery-карточка не восстанавливает MLS-историю. Не объявлять режим готовым к промышленному использованию.

Смена root устройства сохраняет этот модуль и его состояние. Стабильный MLS leaf отделён от меняющегося разрешения входа; маршрут на новый grant меняется атомарно с проверенной серверной ротацией. Это не смена секретов MLS. Поле `manager` внутри зашифрованного Message задаёт передачу управления; его нельзя смешивать с обычным текстом или вложениями. Право автора передавать роль проверяет приложение по подтверждённой истории, а сервер — по своей транзакционной роли.

Локальные инструменты Windows: `. ./tools/mls_environment.ps1` из корня репозитория. Каталог `.local/mls` содержит Rust, Cargo target, анализатор сложности, отчёты и временные файлы и не включается в Git.
